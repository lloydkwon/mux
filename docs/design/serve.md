# `mux serve` — 폰 브라우저 원격 화면 (MVP)

> 관련 코드: serve/ (server.go, auth.go, api.go, backend.go, static/), ui/serve.go(`PhoneRows`),
> tmux/agent.go(`ErrAgentBusy`), tmux/agent_wait.go(`ReadLastTurn`), tmux/transcript.go(`turnPromptText`),
> cmd/mux/serve.go(`newServeCmd`), e2e/serve_e2e_test.go, scripts/tmux-assumptions.sh 19절,
> 받아쓰기는 serve/transcribe.go·dictation.go·static/record.js·scripts/whisper/(아래 «받아쓰기 — 서버 Whisper»),
> 패스키 로그인은 serve/passkey.go·session.go·login.go·static/login.*(아래 «패스키 로그인 — Muxtap»)
>
> 2026-11-17 에 설계하고 같은 날 구현했다. 요청은 claude.ai 대화에서 준비한 요청서(SERVE-REQUEST.md, 커밋하지 않음)였다.

## 무엇이고 무엇이 아닌가

Tailscale 로 폰 브라우저에서 mux 세션 목록을 보고, 세션을 골라 **음성으로 Claude 에게 프롬프트를
보내고**, 세션에 들어가 **마지막으로 보낸 말과 회신, 지금 화면**을 본다. 목록은 패널(`mux watch`)이 세션을
보여 주는 방식을 이어받는다 — 순서·글리프·나이·지금 하는 일을 패널과 같은 판정 함수가 정한다. 그리는
모양은 폰의 것이다: 세션마다 큰 카드(아래 «목록»).

시안(2026-11-17, 3판): https://claude.ai/code/artifact/c504024f-9dad-40d2-95fa-3e42d7f42297 — 1판(패널 줄을
그대로 그린 것)을 본 사용자가 «최근 이벤트는 폰에서 보지 않아도 됨», «세션 정보를 크고 구분이 잘 되게»,
«첫 화면에서 음성으로 했을 때 문자로 표기되는 부분이 필요» 라고 해서 2판이 됐다. 사용자는 2판의 첫 화면을
받아들이고(«처음 화면은 괜찮음») 세션에 들어간 화면과 더 나은 들어가는 방식을 물었다 — 3판이 그 답이다.

```sh
mux serve --allow lloydkwon@gmail.com            # 127.0.0.1:7690 에만 바인드
tailscale serve --bg --https=8443 127.0.0.1:7690  # tailnet 안에서만 https 로 연다
mux serve enroll                                  # 폰 하나를 패스키로 등록할 일회용 코드(10분, 한 번)
```

폰에 보이는 이름은 **Muxtap** 이다(탭 제목·홈 화면·패스키 창). 명령은 그대로 `mux serve` 다.

**하지 않는 것**: 푸시 알림, 번호 없는 메뉴(폴더 신뢰 등)에 답하기,
herdr 소스, funnel(인터넷 공개), 세션 닫기·전환, 새 세션 만들기(보관함 되살리기만 세션을 만든다 — 아래
«보관함 되살리기»). **보내기는 Claude pane 만** 한다 —
`mux agent prompt` 의 확인 절차(입력창 정확 일치·되돌리기)가 Claude 의 `❯` 입력창에만 기대기
때문이다(agent-api.md). 셸·개발 서버 pane 에는 보내기 버튼이 없다.

## 구조 — 새 패키지 `serve/`

```
cmd/mux (serveCmd) → serve → ui (PhoneRows, 순수) → tmux
                          ↘ tmux (ListSessions, WithClaudeWork, Agents, PromptAgent, ReadLastTurn, CapturePaneTarget)
```

- 판정 함수(`aiGlyph`·`sessionAge`·`compactAgo`·`aiWaitingLabel`·`sortByDisplayedAge`, AI 세션과 나머지의
  나눔)는 `ui` 안에 있고 내보내지 않는다. `ui/serve.go` 에 **순수 함수 하나**만 내보낸다:
  `PhoneRows(sessions []tmux.Session) (ai, other []PhoneRow)`. tmux 를 부르지 않으니 «`ui` 에는 목 러너가
  없다» 와 부딪치지 않는다. 패널의 줄 렌더러(`notifyLines`)는 쓰지 않는다.
- I/O 는 `serve` 가 한다. 핸들러는 `backend` 인터페이스(세션 읽기·에이전트 목록·보내기·
  회신·화면)에만 기대고, 테스트는 가짜 backend 를 넣는다. 진짜 backend 는 tmux 함수를 그대로 부르는
  얇은 껍데기이고, 그 배선은 e2e 가 확인한다.
- 정적 파일(`index.html`·`app.js`·`app.css`)은 `//go:embed` — 빌드 단계가 없다. 외부 라이브러리를
  쓰지 않는다(CSP 가 `'self'` 만 허용한다).
- **접속한 클라이언트가 없으면 아무것도 돌지 않는다.** 틱·고루틴·감시가 없고, 모든 일은 요청 안에서
  한다. 목록 계산은 뮤텍스 하나로 줄 세운다 — 탭 두 개가 같은 순간 pgrep·ps 를 두 번 돌리지 않게.
- 정적 파일은 `Cache-Control: no-cache` 다 — 바이너리를 바꿔 띄우면 폰이 새 화면을 받는다. API 는 `no-store`.
- 서버 로그는 한 줄씩: 시작, 거절(이유와 함께), 보내기(«로그인 → pane (세션, 글자 수, force): 갈래»). 글은 적지 않는다.

## 목록 — 패널의 판정, 폰의 카드

`GET /api/list` → `{"ai":[PhoneRow…], "other":[PhoneRow…]}`

```
PhoneRow{session, state("working|approval|ready|shell|none"), glyph, age("41s"), branch, worktree, dir,
         note, work, reason, agents:[{pane, pid, name, state, waitingFor, since}]}
```

- 세션은 패널의 `loadWatchSessions` 와 같다: `tmux.ListSessions()` 다음 `tmux.WithClaudeWork`.
  둘 다 TTL·증분 캐시 뒤에 있다(루트 `CLAUDE.md` 의 표). `agents` 는 `tmux.Agents()` 를 세션별로 묶는다.
- **값은 패널이 정하고, 모양은 폰이 정한다.** 순서(`sortByDisplayedAge`, AI 세션이 먼저), 상태 글리프(`aiGlyph`),
  나이(`sessionAge` → `compactAgo`), 승인 사유(`aiWaitingLabel`), 지금 하는 일(`AIWork`)은 패널과 같은 함수가
  계산한다 — 두 번째 판정을 두면 패널 옆에서 어긋난다. 패널의 줄 렌더러(`notifyLines`)는 쓰지 않는다.
  1판은 그것을 그대로 그렸는데, 13px 고정 폭 줄이 빽빽해 폰에서 세션이 서로 구분되지 않았다(사용자, 2026-11-17).
- **카드 하나가 세션 하나다.** 이름을 크게(19px 고정 폭) 쓰고, 상태는 세 가지로 한 번 더 말한다: 왼쪽 색 띠,
  상태 표(«승인 대기»·«작업 중»·«완료»), 나이의 색. 승인 대기는 카드 바탕까지 붉고, 완료는 흐리게 물러난다 —
  패널의 «가장 흔한 완료가 초록 덩어리가 되지 않게» (panel.md, `aiTextColor`)와 같은 생각이다. Claude 가 없는
  세션은 «다른 세션» 아래 작은 카드다.
- **최근 이벤트는 폰에 없다**(사용자, 2026-11-17). `tmux.LoadEvents()` 도 부르지 않는다. 그래서 «지금 하는 일»
  이 비면(대화 기록이 아직 없음) 카드는 상태 표와 나이만 보인다 — 패널처럼 그 세션의 마지막 이벤트로
  물러서지 않는다.
- **세션 아래 줄의 제목(Haiku)을 짓지 않는다.** `TitleNextClaudeWork` 를 부르지 않고 저장된 답만 읽는다 —
  폰을 열어 둔 것만으로 모델 호출이 나가면 안 된다. 패널이 떠 있지 않으면 제목 대신 원문이 보인다.
- 카드 몸통을 **누르면 보낼 곳**(아래 입력줄의 대상)이 되고, 오른쪽 [›] 나 길게 누르기로 **그 세션에
  들어간다**(아래 «세션에 들어가기»). Claude 가 없는 카드를 누르면 «보낼 수 없다, › 로 화면» 을 알린다.
- 한 세션에 Claude 가 둘 이상이면(짝 합치기 뒤의 exec 세션, pair.md) 입력줄에서 이름·pane 으로 고르게 한다 —
  `ResolveAgent` 가 세션 이름으로는 고르지 않는 것과 같은 이유다. 고르기 전에는 보내기가 꺼져 있다.
- **카드는 줄어들지 않고, 넘치면 목록이 스크롤한다**(`.cards > * { flex: none }`). 카드가 `overflow: hidden` 이라
  flex 의 최소 높이가 0 이 되어, 세션 13개인 폰에서 카드가 화면 높이에 맞춰 눌려 잘렸다(2026-11-17, 시험의 세션 넷으로는
  드러나지 않았다).
- 갱신은 **2초 폴링**이고, 페이지가 가려지면(`visibilitychange`) 멈춘다. 폰 배터리와 서버 일을 같이 줄인다.
  누르고 있는 동안에는 카드를 다시 그리지 않는다(길게 누르기가 끊긴다). 카드와 Claude 고르기 칩은 **내용이 바뀔
  때만** 다시 만든다 — 2초마다 버튼을 갈아 끼우면 pointerdown 과 pointerup 의 대상이 달라져 클릭이 사라진다(데스크톱
  Chrome 에서 칩이 그렇게 눌리지 않았다, 2026-11-17).

## 보내기 — 첫 화면 아래 입력줄, `PromptAgent` 를 그대로

화면 맨 아래에 늘 있는 입력줄: «보낼 곳» 한 줄, [말하기] · 입력칸 · [보내기]. 따로 여는 보내기 창은 없다 —
1판에는 있었는데, 음성으로 보내려면 카드 → 창 → 마이크로 세 번 눌러야 했다. 결과 문구는 입력줄 위에 뜬다.

`POST /api/prompt` `{"pane":"%12","pid":4321,"text":"…","force":false}`

- 대상은 **pane id 와 pid** 로 지목한다. 서버는 그 순간의 `tmux.Agents()` 로 `ResolveAgent(pane)` 를 하고,
  pid 가 다르면 보내지 않는다(«대상이 바뀌었다 — 목록을 새로 고친다»). 목록을 그린 뒤 그 pane 에 다른
  Claude 가 뜬 경우를 막는다. 대화 id 가 아니라 pid 인 이유: `/clear` 는 대화 id 를 바꾸지만 같은 Claude 다.
- `PromptAgent(a, text, force)` 를 그대로 부른다. 검사·잠금·되돌리기는 전부 그 안에 있다. 이 패키지에서
  다시 구현하지 않는다.
- **«작업 중» 을 가르는 값을 하나 더한다** — `tmux.ErrAgentBusy`. 지금 `preparePrompt` 는 «작업 중»
  (force 면 대기열에 들어간다)과 «입력창에 다른 글·복사 모드·synchronize·입력창 없음»(force 로도 안
  되거나 다른 문제다)을 모두 `ErrAgentNotReady` 로 돌려준다. 화면은 앞의 것에만 «대기열에 넣기» 를
  띄워야 한다. 작업 중 갈래만 `fmt.Errorf("%w: %w …", ErrAgentNotReady, ErrAgentBusy)` 로 감싸므로
  `errors.Is(err, ErrAgentNotReady)` 는 그대로 참이고 CLI 의 종료 코드 5 는 바뀌지 않는다.
- 결과는 늘 HTTP 200 에 `{"result": …, "detail": …}` 이다(인증·형식 오류만 4xx). `detail` 은 tmux 의 오류 글이다.
  화면 문구는 클라이언트(`app.js` 의 `RESULTS`)가 정한다:

| 오류 (`mux agent` 코드) | `result` | 화면 문구 | 버튼 |
|---|---|---|---|
| 성공 (0) | `sent` | 보냈다 | — |
| 성공, `force:true` | `queued` | 대기열에 넣었다 — 지금 턴이 끝나면 처리 | — |
| `ErrAgentBlocked` (3) | `blocked` | 승인 대기 중 — 폰에서는 답할 수 없다 | — |
| `ErrAgentBusy` (5) | `busy` | 작업 중 — 대기열에 넣을까요? | [대기열에 넣기] (`force:true` 로 다시) |
| 그 밖의 `ErrAgentNotReady` (5) | `not_ready` | 지금은 보낼 수 없다: <이유> — 아무것도 보내지 않았다 | — |
| `ErrNotSubmitted` (6) | `retry` | 제출되지 않았고 되돌렸다 — 다시 보내도 된다 | [다시 보내기] |
| `ErrPromptUnknown` (1) | `unknown` | 제출됐는지 모른다 — 화면을 확인하고 다시 보내지 말 것 | [화면 보기] |
| `ErrPromptNotSeen` (7) | `not_seen` | 기록에 안 보인다 — 제출은 됐을 수 있으니 다시 보내지 말 것 | [화면 보기] |
| `ErrNoAgent`·`ErrAgentGone`·`ErrAmbiguous`·pid 불일치 | `gone` | 대상 Claude 가 없다 — 다시 고른다 | — |
| `ValidatePromptText` 의 오류 | `invalid` | 그 오류 문구(700자, `!` 시작, 제어 문자…) | — |
| 그 밖의 오류 | `error` | 보내지 못했다: <이유> | — |
| (클라이언트) 답을 받지 못함·5xx | — | `unknown` 과 같다 — 제출됐는지 모른다 | [화면 보기] |

- 7 은 `prompt` 가 내지 않는다(`wait`·`read --after` 의 것이다). MVP 의 회신 탭은 토큰 없이 마지막 턴을
  읽으니 나오지 않지만, 같은 표에 둔다 — 나중에 «폰에서 보낸 것의 회신» 을 읽게 되면 바로 쓰인다.
- `force:true` 는 복사 모드도 빠져나온다(`checkPaneMode`). [대기열에 넣기] 를 누른 사람에게 그 pane 의
  복사 모드는 중요하지 않다고 본다 — 그래도 버튼은 `busy` 에만 뜬다.
- 줄바꿈은 보내기 전에 클라이언트가 공백으로 바꾸고 입력칸에도 그 모양을 보여 준다 — 서버는 한 줄만
  받는다(`ValidatePromptText`). 길이(700자)도 클라이언트가 먼저 센다. 정본은 서버의 검사다.
- `PromptAgent` 는 몇 초 걸린다(입력창 확인 0.6–2초, 제출 확인 5초 × 많아야 2). 버튼은 그동안 «보내는 중» 이다.
- **답을 받지 못하면 «모른다» 다**, «못 보냈다» 가 아니다. 그 몇 초 사이 폰이 잠기거나 망이 바뀌면 fetch 가 실패하지만
  서버는 보내기를 끝까지 한다 — «보내지 못했습니다» 라고 하면 사람이 다시 눌러 두 번 들어간다(리뷰, 2026-11-17).
  응답이 없거나 5xx 면 `unknown` 문구를 띄우고, 4xx 만 «보내지 못했다» 다.
- 결과 알림의 버튼([대기열에 넣기]·[다시 보내기]·[화면 보기])은 결과를 받은 그 Claude(pane·pid)에게만 동작한다. 그 사이
  보낼 곳이 바뀌었으면 알림을 닫고 다시 보내라고 말한다.
- 서버 로그에는 누가·어느 pane 에·몇 글자·결과만 남기고 **글은 남기지 않는다** — 이벤트 기록이
  프롬프트를 담지 않는 것과 같은 이유다(panel.md).

## 세션에 들어가기 — 대화와 화면

카드 오른쪽 [›] 를 누르거나 카드를 길게 누르면 그 세션의 페이지로 넘어간다(옆으로 미는 전환). 시안 3판에서 정했다.

- **들어가는 손잡이는 [›] 가 먼저, 길게 누르기는 지름길이다.** 1·2판은 길게 누르기뿐이었다 — 있는 줄 모르고,
  iOS 에서는 글자 선택·링크 미리보기와 부딪친다. 카드 몸통을 누르는 것은 여전히 «보낼 곳» 이다(2판 첫 화면, 승인됨).
- **아래에서 올라오는 창이 아니라 페이지다.** 주소에 `#s=<세션>` 을 붙인다(`history.pushState`). 폰의 뒤로 가기(iOS
  왼쪽 가장자리 밀기 포함)가 목록으로 돌아오고, 새로 고치거나 Safari 가 탭을 다시 불러도 그 세션에 남는다.
  [‹ 목록] 으로 돌아오면 그 기록을 `history.back()` 으로 지운다 — 우리가 넣은 기록인지는 `history.state.muxPage` 가
  말하고(새로 고쳐도 남는다), 아니면 부르지 않는다(남의 페이지로 물러선다). 주소로 바로 들어왔으면 `replaceState`
  로 `#s=` 만 지운다. 1판의 오른쪽 위 `×` 를 두고 사용자가 «다시 처음 화면으로는 어떻게 돌아오지?» 라고 물었다(2026-11-17).
- 들어가면 포커스는 페이지 자체(`tabindex=-1`)로 옮긴다. [‹ 목록] 에 주면 손가락으로 연 폰에도 포커스 테두리가
  그려졌다(headless 스크린샷으로 확인).
- **입력줄은 그대로 아래에 있고, 보낼 곳이 그 세션이 된다.** Claude 가 둘이면 페이지 머리에서 고르고, 보고 있는
  Claude 가 곧 보낼 Claude 다. 목록으로 돌아와도 보낼 곳은 그 세션으로 남는다 — 쓰던 글이 다른 세션으로 가지 않게.
  Claude 가 없는 세션의 페이지에는 입력줄이 없다.
- **첫 Claude 를 고르는 것은 들어갈 때뿐이다.** 고른 Claude 가 이번 목록에 안 보이면(상태 파일을 덮어쓰는 순간에
  읽어 한 번 빠질 수 있다 — tmux/agent.go 의 찢어진 읽기) 다른 Claude 로 바꾸지 않고 보내기를 끈 채 «지금 목록에
  없다» 고 말한다. 처음 구현은 첫 Claude 로 바꿨고, 고른 Claude 가 돌아와도 바뀐 채 굳어 그 뒤의 보내기가 사람 몰래
  다른 Claude 에게 갔다(리뷰, 2026-11-17 — 상태 파일을 몇 초 치웠다 되돌려 재현하고 고친 뒤 확인). Claude 가 하나만
  남았으면 그것으로 바꾸는 버튼을 보인다. 화면 탭도 그동안은 캡처하지 않는다(세션의 활성 pane 은 다른 pane 일 수 있다).
- 머리: 글리프·이름(22px)·상태 표·나이, 브랜치와 폴더, (둘 이상이면) Claude 고르기. 탭은 [대화] · [화면].
- **대화 탭은 마지막 턴의 «보낸 말» 과 «회신» 이다.** `GET /api/turn?pane=%12&pid=4321` →
  `{prompt:{at,text}, reply:{at,text}}`. `ReadAgentReply` 는 회신만 돌려주므로, 같은 턴의 첫 줄(`findTurn` 의 시작 줄,
  `userText`)을 함께 꺼내는 `ReadLastTurn` 을 tmux 에 더한다. 회신 규칙은 그대로다: 작업 중(`ErrTurnRunning`)이면
  회신 자리에 «작업 중 · 경과» 와 지금 하는 일(`AIWork`), 막혀 있으면 그 대화상자(아래 «대화상자에 답하기»), 글이
  없으면(`ErrNoReply`) 그렇다고 쓴다. 앞 턴의 회신으로 물러서지 않는다(agent-api.md). 마지막 턴이 사람 턴이
  아니면(작업 알림 등) «보낸 말» 대신 그 종류를 쓴다. 기록이 늦게 쓰이면 서버가 2초 × 8번까지 다시 읽는다 — 그동안
  화면은 앞에 읽은 턴을 그대로 두고(처음이면 «읽는 중»), 답이 오면 바꾼다.
  보낸 말은 사람에게 보일 모양으로 다듬는다(`turnPromptText`): 슬래시 명령은 «/이름 인자», 끼워 넣은 블록·붙여 넣기
  태그·이스케이프·방향 문자는 걷고, 여러 줄은 남기고, 4000자에서 자른다.
- **대화는 그 Claude 의 (pane, pid, 상태, 상태 시작 시각) 이 바뀔 때만 다시 읽는다** — 목록 응답의 `agents[].since`.
  기록은 수 MB 일 수 있고, 회신 규칙상 턴이 끝나야 달라진다. 보낸 직후와 탭을 옮길 때는 바로 다시 읽는다.
- **화면 탭은 열려 있는 동안 2초마다 다시 캡처한다.** `GET /api/screen?pane=%12` 또는 `?session=<이름>` →
  `CapturePaneTarget`(`-e`, 색 포함). Claude 가 없는 세션은 활성 pane 을 `=<이름>:` 으로 지목한다 — 콜론까지 써야
  접두사로 다른 세션을 잡지 않는다(park.md, tmux-assumptions 17절). capture-pane 에서도 그렇다 — 19절, 3.8 실측:
  그 이름이 없으면 `=name:` 은 실패하고 맨 이름은 `name-2` 의 화면을 낸다. 화면 대상은 지금 있는 Claude pane(pane+pid)
  이나 지금 있는 세션 이름뿐이다 — 아무 tmux 대상이나 받지 않는다.
  맨 아래를 보고 있으면 따라 내려가고, 위로 올려 읽는 중이면 그 자리에 둔다. 가로는 스크롤한다.
- 회신은 글 그대로(`white-space: pre-wrap`), 마크다운을 그리지 않는다.

## 대화상자에 답하기 — 질문·권한 확인

Claude 가 AskUserQuestion 질문이나 권한 확인(도구 실행 허락)을 띄우고 기다리면(상태 `blocked`), 세션 페이지의 대화 탭이
그 대화상자를 그리고 폰에서 답한다. 처음 설계에서 2차로 미뤘다가, 사용자가 폰에서 nse 의 질문에 답하지 못해 «폰에서의
작업이 어렵다» 고 해서(2026-11-17) 들였다. 코드: tmux/agent_dialog.go, serve/dialog.go, app.js 의 `dialogBox`.

**실측**(2026-11-17, Claude Code 2.1.312, 격리 tmux 서버의 haiku — 화면은 tmux/testdata/dialog):

| | 한 개 고르기 질문 | 여러 개 고르기(multiSelect) | 권한 확인 |
|---|---|---|---|
| 모양 | `❯ 1. 글` 번호 목록, 아래 들여 쓴 설명. 맨 위 탭 줄 `← ☐ 방식 ☐ 주기 ✔ Submit →` | `❯ 1. [ ] 글` 체크박스, 끝에 번호 없는 `Submit` 줄 | ` ❯ 1. Yes`(한 칸 들여 씀), 긴 선택지는 접힌다 |
| 숫자키 | 고르고 바로 확정 → 다음 질문 탭, 마지막 뒤에는 Submit 탭(검토) | **체크만 켜고 끈다**(커서 그대로, 넘어가지 않는다) | 고르고 확정 |
| 직접 쓰기 | `Type something.` — 숫자키가 커서만 옮기고, 친 글이 그 자리에 보이며 Enter 로 확정 | `[ ] Type something`(마침표 없음) — 숫자키는 체크만, **화살표로 커서를 옮겨야** 글이 들어간다 | 없음 |
| 커서가 직접 쓰기 칸에 있을 때 숫자키 | **글자로 들어간다** — `❯ 3. 1`, 고르지 않는다 | **글자로 들어가고 체크된다** — `[✔] 1` | — |
| 넘어가기 | 숫자키 | Submit 줄까지 화살표 → Enter → Submit 탭 | 숫자키 |
| 상태 파일 | `waiting` / `input needed` | 같다 | `waiting` / `permission prompt` |
| Esc | 질문 전체를 «User declined to answer questions» 로 | 같다 | 거절 |

Submit 탭(검토 «Review your answers», `1. Submit answers / 2. Cancel`)에는 안내 줄(`Esc to cancel`)이 없다 — 처음에는
화면이 차서 안 보이는 줄 알았는데, 빈 줄이 남는 화면에서도 없었다. 폴더 신뢰처럼 **번호 없는 메뉴**도 있다 — 숫자키로 답할
수 없어 대화상자로 내지 않는다(화면 탭으로 본다).

직접 쓰기 칸(같은 날 리뷰 뒤에 잰 것): 칸에 글이 들면 `Type something` 이 그 글로 바뀐다. 칸은 질문의 선택지 덩어리를
가르는 `─` 선 바로 위 번호이고(그 아래가 `Chat about this`), 권한 확인과 Submit 탭에는 선택지 사이에 선이 없다. 화살표로
칸을 나가도 글은 남고, 다시 들어오면 **글 커서가 맨 앞**이라 BSpace 가 먹지 않는다 — End 뒤 BSpace 로 지운다. 빈 칸의
BSpace 는 아무것도 하지 않는다. 여러 개 고르기에서 글을 다 지우면 체크도 꺼지고, 커서가 밖에 있을 때 그 칸의 숫자키는
빈 채로 체크만 바꾸며, **체크를 끈 칸의 글은 제출되지 않는다**(검토 탭에 안 나온다).

- **찾기**(`parseDialog`): 아래에서 위로 1 부터 이어지는 번호 목록의 마지막 덩어리를 찾고, 그 위의 가장 가까운 `─` 선을
  시작으로 본다(권한 확인 안의 `╌` 점선은 아니다). 시작 선 바로 아래에 탭 줄이 있거나, 선택지 아래에 `Esc to cancel`
  안내 줄이 있어야 대화상자다 — 사람이 입력창에 친 `1. …` 이나 회신 속 번호 목록을 걸러 낸다. 직접 쓰기 칸은 라벨이 아니라
  **자리**로 안다(선택지 사이 `─` 선 바로 위 번호, 여러 개 고르기는 마지막 체크박스) — 라벨로만 알면 칸에 글이 든 순간
  보통 선택지로 보여 숫자를 누른다. 칸에 든 글은 `Draft` 로 폰에 보인다.
- **누르기 직전에 화면을 다시 읽어, 폰이 본 대화상자(`Key`)와 선택지(번호와 글)일 때만 누른다**(`AnswerDialog`, 아니면
  `changed` 로 아무것도 누르지 않는다). 측정하다 Submit 탭이 떠 있는 줄 모르고 `2` 를 눌러 질문 전체가 Cancel 된 일이 있다 —
  낡은 화면을 보고 누른 숫자는 엉뚱한 답이 된다. **번호와 글만으로는 모자란다**(리뷰 차단): 권한 확인은 어느 것이나
  `1. Yes` 라, 폰이 권한 확인 A 의 Yes 를 고른 사이 PC 에서 A 에 답하고 B(`rm -rf dist`)가 뜨면 보지 않은 B 를 승인한다.
  그래서 `GET /api/dialog` 가 대화상자의 열쇠(종류·탭·글·선택지의 번호·글·설명의 해시 — 커서와 체크는 뺀다, 답하는 동안
  우리가 바꾸는 것이라)를 주고, 답하기·여러 개 고르기·Esc 모두 그 열쇠를 돌려보내야 누른다. 폰도 새로 읽은 열쇠가
  다르면 고르던 선택지·Esc 확인·체크를 푼다. 그 밖의 확인: 막힘 상태, 복사 모드 아님(키가 모드로 간다), pane
  잠금(보내기와 같은 flock).
- **커서가 직접 쓰기 칸에 있으면 숫자를 누르기 전에 화살표로 한 칸 빼낸다**(`leaveFreeSlot`, 리뷰 차단) — PC 에서 화살표로
  그 칸에 커서를 두었거나 앞선 시도가 남긴 경우다. 빼내지 않으면 숫자가 칸에 글자로 들어가고, 칸의 글이 바뀌어 «넘어갔다»
  로 읽혀 `answered` 라고 거짓말을 한다(가짜 Claude 로 재현, 진짜에서도 같다).
- 누른 뒤 대화상자가 넘어갔는지(닫혔거나, 탭·글·선택지·체크·커서가 바뀌었거나, 상태가 막힘에서 벗어났거나) 3초 안에
  본다. 그대로면 `unknown` — 같은 모양의 다음 대화상자일 수도 있어 «안 들어갔다» 고 하지 않는다.
- **직접 쓰기**: 숫자키로 커서를 옮기고(이미 칸에 있으면 누르지 않는다 — 글자가 된다) → 쓰다 만 글이 있으면 End 뒤
  BSpace 로 지우고(폰이 그 글을 보고 골랐다, 열쇠에 그 글이 들어 있다) → 칸이 빈 것을 보고 → 글을 한 번 치고 → 칸에
  정확히 그 글이 보일 때만 Enter(mux agent prompt 와 같은 원칙). 다르게 보이면 커서가 아직 그 칸일 때만 친 만큼 BSpace 로
  되돌리고 `unknown` 이다. 글은 아래 입력줄(말하기 포함)에서 쓴다 — 고르는 동안 입력줄은 «답 · 직접 쓰기» 다.
- **여러 개 고르기**(`AnswerMulti`): 폰에서 체크박스를 켜고 끄는 동안은 아무것도 보내지 않는다. «고른 N개로 다음 →» 을
  누르면, 서버가 폰이 본 대화상자(열쇠)와 체크박스 전부(번호·글)가 지금 화면과 같은지 보고 → 커서가 직접 쓰기 칸이면
  빼내고 → 다른 체크만 숫자키로 맞추고(하나씩 다시 읽어 확인, 바라지 않는 칸의 쓰다 만 글은 체크만 끈다) → 직접 쓰기 글이
  있으면 화살표로 그 칸에 가서 쓰다 만 글을 지우고 치고 → 화살표로 Submit 줄에 가서 커서가 거기 있고 체크가 모두 바란
  대로인 것을 본 뒤 Enter 한다. 그러면 Submit 탭(검토)이 뜨고, 제출은 한 개 고르기처럼 확인을 한 번 더 받는다. 한 개 답하기(`AnswerDialog`)는 여러
  개 고르기를 거절한다 — 숫자키가 체크만 바꿔 «답했다» 고 잘못 말하게 된다.
- **확인 한 번 더**(사용자 결정): 선택지를 누르면 «‹글› 로 답하기» 버튼이 떠야 보낸다. 권한 확인은 명령 실행 허락이라 잘못
  누르면 되돌릴 수 없다. «답하지 않고 닫기(Esc)» 도 «닫기 / 아니요» 를 한 번 더 묻는다.
- 대화 탭은 **내용이 바뀔 때만 다시 그린다** — 2초마다 갈아 끼우면 선택지 버튼이 누르는 사이 바뀌어 클릭이 사라진다(칩과
  같은 문제). 회신 글을 손가락으로 골라 복사할 수 있게 된 것도 이것 덕분이다(리뷰 권고).
- 상태 파일의 `waiting` 이 화면보다 먼저 쓰일 수 있다(가짜 Claude 로 재현) — 폰은 막혀 있는 동안 2초마다 대화상자를 다시
  읽으니 잠깐의 «읽는 중» 으로 끝난다.

`GET /api/dialog?pane&pid` → `{result: ok|none|gone|error, dialog: {key, kind, tabs, prompt, options[{n,label,detail,chosen,
freeText,draft,checkbox,checked}], current, hint, multi}}`. `none` 이면 폰은 «번호로 고를 수 있는 대화상자가 아닙니다» 를
띄우고 화면 탭을 권한다(폴더 신뢰 같은 번호 없는 메뉴).
`POST /api/answer` `{pane, pid, key, n, label, text?}` · `{pane, pid, key, multi: true, options: [{n,label,checked}], text?}` ·
`{pane, pid, key, cancel: true}` → `{result, detail}`. `key` 가 없으면 400 이다:

| 오류 | `result` | 화면 문구 |
|---|---|---|
| 성공 / 취소 성공 | `answered` / `cancelled` | 답했습니다 / 대화상자를 닫았습니다 |
| `ErrDialogChanged` | `changed` | 대화상자가 바뀌었습니다 — 누르지 않았으니 새 화면을 보고 다시 고르세요 |
| `ErrNoDialog` | `none` | 대화상자가 이미 닫혔습니다 |
| `ErrAnswerUnknown` (·응답 없음·5xx) | `unknown` | 답이 들어갔는지 알 수 없습니다 — 화면 탭에서 확인 |
| `ErrAgentNotReady` | `not_ready` | 지금은 답할 수 없습니다(복사 모드 등) |
| `ErrAnswerText`·글 검사 | `invalid` | 보낼 수 없는 글입니다 |
| `ErrNoAgent`·`ErrAgentGone`·pid 불일치 | `gone` | 대상 Claude 가 없습니다 |

로그에는 «몇 번», «여러 개 고르기 N개», «직접 쓰기 N자» 만 남기고 선택지 글과 직접 쓴 글은 남기지 않는다.

TUI 의 `p` 로 보관한 세션([park.md](park.md))을 폰에서 보고 되살린다. 그전에는 되살리는 입구가 TUI 의 `P` 하나뿐이라
폰으로 일하는 동안 보관한 대화로 돌아갈 길이 없었다(사용자 요청, 2026-11-17). **보관하기(`p`)와 지우기(`d`)는 폰에 두지
않는다** — 보관은 세션을 닫고, 지우기는 대화로 가는 길을 지운다. 되살리기는 아무것도 지우지 않는다(못 띄운 대화는 항목에
남는다).

**같은 함수를 부른다.** 서버는 `tmux.LoadParked`(읽기)와 `tmux.RestoreParked`(되살리기)를 그대로 부르고, 보관 코드는
고치지 않는다. 같은 대화 id 로 `--resume`, 이미 살아 있는 대화는 띄우지 않고 그 세션으로 감, 폴더·기록이 사라진 대화는
항목에 남김, `=name:` 지목, `-c` 의 `#` 이스케이프 — 전부 park.md «복원» 그대로다. 다른 점은 attach 가 없다는 것뿐이다:
폰은 세션에 붙지 않고, 되살린 세션이 목록에 카드로 나타난다. `RestoreParked` 는 `tmux new-session … claude --resume <id>`
로 띄운다 — TUI·`--claude` 입양과 같은 길이고, 사용자 서버에서 그렇게 뜬 kream-matching·works 가 `claude` 를 돌리고 있다
(2026-11-17 `pane_start_command` 로 확인). mux-serve 의 PATH 에도 `~/.local/bin` 이 있다. 새 세션은 만든 클라이언트(여기서는
mux-serve)의 `update-environment` 변수를 받는다 — mux-serve 의 `SSH_AUTH_SOCK` 은 gnome-keyring(`/run/user/1000/keyring/ssh`)이고,
kream-matching·works 도 같은 값이며, 키(ED25519 둘)를 가진 것도 그쪽이다(gpg-agent 쪽은 «no identities», 2026-11-17 확인).
되살린 Claude 의 `git push` 는 다른 mux 세션과 같은 에이전트를 쓴다.

```
목록 맨 아래  보관함 · 5  ▸            ← 누르면 펼친다(처음엔 접힘 — 카드 목록을 밀어내지 않게)
              ┌──────────────────────────────────────┐
              │ ≡ sekihe-2                  6시간 전 │
              │   sekihe-boseshop · sekihe-boseshop-a7 │  ← 폴더 · Claude 가 붙인 작업 이름(첫 대화)
              │   메모 한 줄(있으면)        [되살리기] │
              └──────────────────────────────────────┘
[되살리기] → 같은 자리에 «‹sekihe-2› 를 되살릴까요? [되살리기] [아니요]» → 서버 → 성공하면 그 세션 페이지(#s=이름)로
```

- **확인 한 번 더**(대화상자 답하기와 같은 생각) — Claude 를 띄우는 일이라 잘못 누른 손가락으로 일어나면 안 된다.
- **되살리면 그 세션 페이지로 간다**(TUI 의 «복원하면 바로 그 세션으로 간다» 와 같다). 목록은 그 전에 직접 다시 읽는다 —
  진행 중인 폴링을 기다리면 낡은 목록으로 «이 세션이 목록에 없습니다» 가 보였다(리뷰). 막 띄운 Claude 가 아직 안 잡혔으면
  «Claude 없음» 으로 열리고, 다음 폴링이 그 Claude 를 보낼 곳으로 잡는다.
- **일부만 되살렸으면 목록에 머문다.** 페이지로 넘어가면 `showPage` 가 알림을 지우고, 막 띄운 Claude 가 안 잡혔으면 입력줄째
  숨어 경고가 한 번도 보이지 않았다(리뷰가 찾음). 목록에서 이유와 함께 알리고, 세션은 카드의 › 로 들어간다.
- 대화가 둘 이상이면(exec/plan 짝) 카드에 «대화 2» 를 보인다. opencode 대화에 도구 이름을 붙이는 것은 보관 코드에
  `tool` 필드가 들어온 뒤다(지금 커밋에는 없다 — 다른 작업이 더하는 중). 되살리기는 그 필드 없이도 같은 함수가 맡는다.
- **보관한 지 오래면 알린다**: Claude 는 오래된 기록을 지운다(`cleanupPeriodDays`, 이 기계는 설정 없음 — 기본값을 쓴다. 기본값은
  30일로 알려져 있지만 확인하지 않았다). 25일이 넘은 항목에는 «곧 기록이 지워질 수 있음» 을 흐리게 붙인다. 판정은 보관
  시각뿐이다 — 기록 파일을 열어 보지 않는다.

`GET /api/list` 에 `parked: [{id, name, note, parkedAt(ms), conversations:[{task, dir}]}]` 와 `parkedError` 를
더한다(최근에 보관한 것이 먼저, 폴더는 집을 `~` 로). 보관함 파일은 수 KB 라 목록을 읽을 때마다 읽는다. 깨진 파일은 목록을
막지 않는다 — 카드는 그대로
그리고 보관함 자리에 «보관함을 읽지 못했습니다» 를 쓴다(park.md: 깨진 파일은 빈 목록이 아니라 오류다).

`POST /api/unpark {"id": "…"}` → `{result, session?, detail?}`:

| `RestoreParked` 의 결과 | `result` | 폰 |
|---|---|---|
| 이름 있고 오류 없음(이미 살아 있던 대화면 그 세션, 메모·태그 실패는 `RestoreParked` 가 삼킨다) | `restored` | 그 세션 페이지로 |
| 이름 있고 오류 있음(일부 대화만 띄움, 또는 다 띄웠는데 보관함을 고치지 못함 — 둘은 오류로 가를 수 없다) | `partial` | 목록에 머물며 «되살렸지만 다 끝내지 못했습니다: 이유» |
| 이름 없음(아무것도 못 띄움, 항목 그대로) | `failed` | «되살리지 못했습니다: 이유»(폴더·기록이 사라짐 등) |
| 그 id 가 보관함에 없음(다른 곳에서 되살렸거나 지움) | `gone` | 목록을 새로 고침 |

- 서버는 **그 순간의 보관함을 다시 읽어** id 로 찾는다 — 폰이 본 목록은 낡았을 수 있다(TUI 가 그사이 되살림).
- 되살리기는 서버 안에서 한 번에 하나다(뮤텍스). 두 손가락이 같은 항목을 겹쳐 눌러도 두 번째는 앞의 것이 끝난 뒤 보관함을
  다시 읽어 `gone` 이다 — 같은 대화를 두 번 띄우지 않는다. 항목이 일부 남은 경우의 다시 누르기는 `RestoreParked` 의 살아 있는
  사본 판정이 막는데, 그 판정은 새 Claude 의 상태 파일에 기댄다 — 상태 파일이 쓰이기 전(1–2초)에 다시 누르면 `이름-2` 로 한 번
  더 뜰 수 있다(재지 않음).
- 인증은 다른 POST 와 같다(신원 헤더·Host·Origin·JSON). 로그는 «되살리기 로그인 → 이름 (대화 N개): 결과[: 이유]» — 이유(못 띄운
  대화의 짧은 id·폴더, tmux 오류)도 남긴다, 폰의 알림은 닫히면 사라진다. 보관함에 없는 id 는 인용하고 64자로 잘라 적는다 — 폰이
  보낸 글로 로그 줄을 꾸며 넣지 못하게.
- TUI 와 함께 쓰는 경합은 TUI 둘 사이에 이미 있던 것과 같다 — 잠금이 없다. 되살리기의 `keepParked`·`ForgetParked` 는 읽고-고치고-
  쓰기만 하고 다시 읽지 않는다(쓴 뒤 다시 읽어 확인하는 것은 보관 `ParkSession` 뿐). 그래서 폰의 되살리기와 TUI 의 보관이 수십 ms
  안에 겹치면 방금 보관한 항목이 덮일 수 있고, TUI 는 팝업을 열 때 읽은 사본으로 되살리므로 폰이 막 되살린 Claude 의 상태 파일이
  쓰이기 전이면 둘 다 띄울 수 있다. 사람 한 명의 손가락 속도라 받아들인다.
- **되살리기는 직전 되살리기와 같은 초면 다음 초까지 기다린다**(`lastUnpark`, 뮤텍스 아래). `session-created` 훅의 resurrect
  스냅숏은 초 단위 파일 이름에 원자적이지 않게 써서, 한 초에 세션 둘이 생기면 한 파일에 섞이고 그것으로 복원하면 pane 이 두 배가
  된다(tmux/claude_sessions.go 의 `waitForNextSecond` — `--claude` 입양이 초 경계를 기다리는 이유, 리뷰가 짚음). 폰과 TUI 가 같은
  초에 만드는 겹침은 남는다.

**하지 않는 것**: 띄우기 전에 «되살릴 수 있는지»(폴더·기록이 있는지) 미리 보이기 — 그 판정(`planUnpark`)은 tmux/park.go 안에
있고, 지금 다른 작업(opencode 보관)이 그 파일을 고치는 중이다. 실패는 되살리기를 눌렀을 때 이유와 함께 알린다. 그 작업이
들어온 뒤 판정 함수를 내보내 카드에 미리 보이는 것을 2차로 둔다.

- 폰의 카드는 `.card` 가 아니라 `.pcard` 다 — 누르기(보낼 곳)·길게 누르기(들어가기)를 받지 않는다. 이름 뒤에는 «세션» 을
  붙여 조사를 고정한다(«‹이름› 세션을 되살렸습니다»). 되살리는 중에는 다른 항목의 [되살리기] 도 꺼진다.
- 답을 받지 못하면 «되살렸는지 알 수 없습니다» 다 — 다시 눌러도 서버가 살아 있는 대화를 다시 띄우지 않는다고 말한다.
- **보관함의 버튼을 누르는 동안은 카드를 다시 그리지 않는다**(`parkPress`). 2초 폴링이 누르는 사이 버튼을 바꾸면 클릭이 사라진다 —
  칩에서 있던 일과 같고, 확인까지 두 번 누르니 더 잘 걸린다(리뷰가 찾음). 손가락이 떨어지면(`pointerup`, 버튼 밖에서도) 한 박자
  뒤에 풀어 같은 손가락의 click 이 먼저 처리되게 하고, 그 신호가 끝내 없으면 10초 뒤에 푼다. 처음에 1.5초로 푼 판은 누른 채 2.6초
  둔 시험에서 버튼이 바뀌었다.
- 깨진 보관함은 접힌 머리에 숫자 대신 «읽지 못함» 이다 — «0» 이면 빈 보관함으로 읽힌다.

## 화면 탭의 ANSI → HTML 은 클라이언트가

- 목록은 이제 ANSI 를 쓰지 않는다 — 화면 탭(`capture-pane -e`)만이다.
- 서버는 캡처한 바이트를 그대로 보낸다. `app.js` 의 작은 해석기가 SGR(0·1·2·3·4·7·22–27,
  30–37·90–97·38;5·38;2·39, 배경도 같다)만 읽고 나머지 이스케이프(OSC 8 등)는 버린다.
- **글은 언제나 `textContent` 로 넣는다.** pane 내용·세션 이름·오류 문구 모두 남이 정할 수 있는 글이다.
  `innerHTML` 은 카드의 [›] 아이콘(고정된 문자열)에만 쓴다.
- 색은 ANSI 인덱스를 CSS 변수(`--a0`…`--a15`, 밝은·어두운 테마 두 벌, `prefers-color-scheme`)로 가리키고, 256색·
  트루컬러는 값을 계산해 모두 CSSOM(`element.style`)으로 칠한다 — CSP 의 `style-src 'self'` 는 style 속성 글을 막지만
  CSSOM 은 막지 않는다. 패널의 색 원칙(«팔레트는 터미널의 것», rendering.md)과 같다 — 우리가 고르는 것은 16색 표 하나뿐이다.
- **넓은 글자는 2칸 상자로 감싼다.** 폰의 고정 폭 글꼴에는 한글이 없어 대체 글꼴로 그려지고, 그 폭이
  정확히 2칸이 아니다 — Claude 의 `─` 선과 대화상자 테두리가 흔들린다. ASCII 가 아닌 글자는 `inline-block` 에
  폭 `1ch`·`2ch` 를 주어 칸에 맞춘다. 폭 판정은 JS 의 범위 표(한글·CJK·전각·이모지)이고, Go 의
  `ansi.StringWidth` 와 어긋나면 그 줄의 정렬만 틀린다(뜻은 그대로다).

| 틀린 용어 / 12 | 10 | 7 | 4 | **2** — herdr(허더)·systemd(시스템 뒤에) |
| 일반 낱말 틀림 | 4 (플래그→블랙, 패널에→패널 노래, 폭→쪽, 세션→세트) | 1 (기준→기지) | 1 | 1 |
| 빠진 말 | «herdr 워크» | 없음 | 없음 | 없음 |

Safari 는 따로 받아쓴 것이라 발음이 같지 않다. Whisper 는 large-v3-turbo, 41초 iPhone 음성 메모. 셋째 칸은 처음 측정 —
`model.transcribe`(순차)에 «개발 대화. 용어: 목록.» — 이고, 넷째 칸이 구현한 것(묶음 처리 + 머리말 없는 목록, 아래
«되돌리면 안 되는 설정»)이다. 셋째 칸에서 안 고쳐진 go vet·golangci-lint 는 녹음의 30초 뒤에 있어 **프롬프트를 받지
못한 것**이었다(검토에서 찾음). 사용자 결정: faster-whisper 를 GPU 로, 듣는 동안은 녹음 시간만 보인다.

```
폰        [말하기] → getUserMedia → MediaRecorder(audio/webm;codecs=opus, 없으면 audio/mp4) — «녹음 중 0:12»
          [그만] 또는 2분 → POST /api/transcribe (본문 = 녹음 그대로, Content-Type = 녹음 형식) — «받아쓰는 중…»
mux serve 인증 → 한 번에 한 건 → 임시 파일(0600) → <--whisper 명령> --prompt=<용어> <파일>  (요청이 끊기면 죽인다)
          → stdout {"text": …} → 바꿔 쓰기 표 → {"result":"ok","text":…}
폰        입력칸의 글 뒤에 붙인다 — 저절로 보내지 않는다(지금과 같다)
```

**켜고 끄기.** `mux serve --whisper <명령>`. 비면 꺼짐이고(제로값), 지금의 브라우저 받아쓰기(아래 «음성»)가 그대로 돈다.
폰은 처음에 `GET /api/features` → `{"dictation":"whisper"|"browser"}` 로 안다. MediaRecorder 가 없으면 처음부터, 녹음을
시작하지 못하면 그 뒤로 이 페이지는 브라우저 받아쓰기다 — 곧바로 띄우지 않고 «다시 누르면 브라우저 받아쓰기» 라고 알린다(마이크를
묻고 실패한 뒤라 사용자 동작 밖이고, Safari 의 받아쓰기가 그때 시작해 주는지 모른다). 받아쓰기가 404 면(서버가 `--whisper`
없이 다시 떴다) 같은 식으로 물러선다. 마이크 권한을 거절당했을 때는 물러서지 않는다 — 브라우저 받아쓰기도 같은 마이크를
쓴다 — 허용하는 자리(주소창의 aA › 웹사이트 설정 › 마이크)를 알린다. `--whisper` 는 띄울 때 `exec.LookPath` 로
확인한다 — 없는 명령이면 받아쓰기를 처음 누를 때가 아니라 시작할 때 실패한다. 용어 파일의 기본 자리는 `--dictation` 이고,
제로값(빈 경로)은 «읽지 않음» 이라 `go test ./serve` 가 개발자의 `~/.config/mux` 에 닿지 않는다.

**받아쓰기 명령 — `mux serve` 는 Python 을 모른다.** 계약은 `<명령> --prompt=<글> <오디오 파일>` → stdout 에 JSON 한 줄
`{"text": "…"}`(있으면 `"duration"`·`"speech"` — 녹음 길이와 VAD 가 말소리로 본 길이, 받아쓰기 기록에만 쓴다), 종료 코드 0. 그 밖은 실패다. 셸을 거치지 않는다(exec). 프롬프트는 `--prompt=` 한 덩어리다 — `--prompt <글>`
로 나눠 넘기면 `-` 로 시작하는 프롬프트(용어가 `--resume` 하나뿐)를 argparse 가 옵션으로 읽어 매번 실패한다(진짜 명령으로
확인). 명령은 저장소의 `scripts/whisper/`:

- `setup.sh` 가 `~/.local/opt/mux-whisper/` 에 uv 가상환경을 고정 버전으로 만든다 — faster-whisper 1.2.1, av 15.1.0
  (19 는 1.2.1 이 넘기는 `metadata_errors` 를 받지 않아 열지 못했다), ctranslate2 4.8.5, nvidia-cublas-cu12 12.9.3.13,
  nvidia-cudnn-cu12 9.27.0.42. CUDA 라이브러리는 pip 의 것이라 sudo 도 CUDA 툴킷도 필요 없다. `LD_LIBRARY_PATH` 를 거는
  `transcribe` 래퍼를 두고, 모델(1.6GB)은 setup 때 받는다 — 첫 요청이 내려받기를 기다리지 않게.
- `transcribe.py` 는 `language="ko"`, `beam_size=5`, `device="cuda"`, `compute_type="float16"`. CUDA 를 못 쓰면 실패로
  끝난다 — CPU 로 몰래 물러서지 않는다(몇십 초가 걸리는데 폰은 이유를 모른다). 받아쓴 글은 stdout 에만 쓴다.
- **요청마다 띄운다.** 41초 녹음이 1.6초(Python 시작과 모델 읽기까지, 묶음 처리 — `check.sh`)였고, GPU 메모리는 도는
  동안만 쓴다(82초 녹음에서 최대 2.6GB, 순차는 2.3GB). m4a(AAC)·webm(Opus)을 PyAV 가 바로 읽는다(0.83·0.74초, 같은 글) —
  ffmpeg 가 필요 없다. 상주 서버는 두지 않는다(«접속한 클라이언트가 없으면 아무것도 돌지 않는다»).

**되돌리면 안 되는 설정**(2026-11-17, 같은 녹음으로 잼):

- **묶음 처리(`BatchedInferencePipeline`)** — 순차 `model.transcribe` 는 이어쓰기를 끄면 첫 30초 창 뒤에 프롬프트를 버린다
  (faster-whisper 1.2.1 `prompt_reset_since = len(all_tokens)`). 같은 녹음을 두 번 이은 82초에서 순차는 뒤 절반이 «묵스·티묵스·
  인텔리제이·파이참·이 두위» 로 돌아갔고, 묶음 처리는 VAD 로 자른 30초 이하 조각마다 프롬프트를 붙여 두 절반 모두 mux·tmux·
  IntelliJ·PyCharm·e2e·go vet·golangci-lint·origin·push 를 맞혔다. 무음·잡음은 그대로 빈 글이고 더 빠르다(82초 0.85초,
  순차 1.24초). 묶음 처리의 기본값 `without_timestamps=True` 를 바꾸지 않는다 — 타임스탬프를 켜자 3초 조각이 «go vet, go
  vet, …» 를 열두 번 되풀이했다. 낱말 중간에서 자른 3–4초 조각 여섯은 순차와 묶음이 번갈아 나았다(묶음은 5개 용어
  프롬프트에서 «mux 패널에서» 를 «mux, panel.» 로, 순차는 «커밋 메시지» 를 «commit message» 로) — 짧은 실제 발화는 폰에서 본다.
- `vad_filter=True` — 끄면 8초 무음·잡음에서 «다음 영상에서 만나요.» 를 지어냈다(whisper.cpp 는 «감사합니다.»). 켜면 빈 글이다.
- `condition_on_previous_text=False` — 순차에서 켜 둔 채 프롬프트를 주면 마지막 문장을 여섯 번 되풀이하거나 뒤 절반이 «Opt if
  the bend for the bend…» 가 됐고, 돌릴 때마다 달랐다(온도 폴백). 묶음 처리는 늘 끄지만 뜻을 남겨 둔다.
- `hotwords` 를 쓰지 않는다 — «Go, pect,» 에서 끊겨 뒷부분을 잃었다.
- 프롬프트는 문장이 아니라 **목록**이다 — 문장으로 쓴 프롬프트는 «kitty 기준» 을 «pt기즈», mux 를 «mx» 로 바꿨다.
- 프롬프트에 **머리말을 붙이지 않는다.** 브라우저 시험에서 3초짜리 녹음이 «용어:" mux 패널에서» 로 나왔다 — 짧은 말에서는
  프롬프트의 글이 받아쓴 글로 샌다. 같은 녹음을 잘라 견줬다(용어 26개, 순차 처리 때 잰 것 — 묶음 처리에서도 목록만 둔 3초
  조각은 «mux 패널에서» 였다):

  | 프롬프트 | 3초 «mux 패널에서» | 41초 전체에서 놓친 용어 |
  |---|---|---|
  | «개발 대화. 용어: 목록.» | «용어. mux 패널에서» | 없음 |
  | «개발 대화. 목록.» | 바름 | Haiku(하이쿠)·e2e(이트위) |
  | «목록.» (지금) | 바름 | e2e(이트위) |

  잘라 낸 다른 조각(3–5초 넷)은 셋 다 같았다. 낱말 중간에서 자른 2초 조각은 프롬프트가 없어도 엉뚱한 말(«그 다음에 거기서»)이
  나왔다 — 아주 짧은 녹음은 원래 믿을 수 없다. 순차에서 목록만 두면 놓치던 e2e 는 묶음 처리에서 맞았다.

**용어와 바꿔 쓰기 — `~/.config/mux/dictation.txt`.** 한 줄에 하나: `용어` 는 프롬프트로, `틀린 말 => 바른 말` 은 받아쓴 뒤
바꿔 쓰기로, `#` 은 주석. 요청마다 읽는다(고친 뒤 다시 띄울 필요가 없다). 파일이 없으면 세션 이름만 쓴다.

- 프롬프트는 지금 세션 이름 + 파일의 용어를 쉼표로 늘어놓고 마침표로 끝낸 목록이다(`dictationPrompt`). 숫자뿐인 세션 이름은
  빼고, 파일 용어와 겹치는 이름은 파일 쪽에 한 번만 둔다. faster-whisper 는 프롬프트의 **끝** 223 토큰만 쓴다(`get_prompt`)
  — 넘치면 앞의 세션 이름부터 잘리도록 사람이 고른 파일 용어를 뒤에 둔다. 용어 26개가 97 토큰(머리말 포함)이었다. tmux 를
  읽지 못하면 세션 이름 없이 받아쓴다.
- 바꿔 쓰기는 글자 그대로(정규식이 아니다), 파일 순서대로. 프롬프트로 안 고쳐진 herdr·systemd 가 이 표의 몫이다. 잘못
  바뀌어도 사람이 입력칸에서 보고 고친다 — 저절로 보내지 않는다.

**서버 — `POST /api/transcribe`.**

- 인증은 다른 POST 와 같다(신원 헤더·Host·Origin). Content-Type 은 이 경로에서만 `audio/webm`·`audio/mp4` 를 받는다. 둘 다
  CORS 의 단순 요청 형식이 아니어서 다른 출처는 사전 요청 없이 보내지 못한다 — JSON 만 받는 이유와 같다. 단순 요청 형식인
  `multipart/form-data`·`text/plain` 은 받지 않는다.
- 본문 상한 10MB(413). 폰은 32kbps 로 녹음한다(`audioBitsPerSecond`, 2분 약 0.5MB) — Chrome 의 기본값으로는 2분이 1.9MB
  였고, 32kbps Opus 로 바꾼 녹음은 원본과 같은 글이 나왔다. 41초 AAC 음성 메모는 0.7MB. 한 번에 한 건이고 겹치면 `busy`.
- 녹음은 0600 임시 파일에 쓰고 끝나면 지운다. 명령은 요청의 context 에 60초 상한을 걸어 돌린다 — 폰이 끊으면(잠김·망 바뀜,
  보내기를 눌러 거둠) 프로세스를 죽인다. **프로세스 묶음째 죽인다**(`Setpgid` + `kill(-pgid)`) — 래퍼가 exec 하지 않았거나
  자식을 띄웠어도 GPU 를 쥔 Python 이 남지 않게. stdout 은 64KB 까지 읽고, 오류는 stderr 의 마지막 줄이다.
- 서버 전체의 ReadTimeout(15초)·WriteTimeout(60초)은 JSON 요청에 맞춘 것이라, 이 요청만 `http.ResponseController` 로
  읽기 60초·쓰기 130초로 늘린다(느린 망의 녹음 올리기와 받아쓰기).
- 요청의 context 는 서버의 수명에서 나온다(`BaseContext`) — 끌 때(`Shutdown` 은 도는 요청을 취소하지 않는다) 받아쓰기를
  죽이고 임시 녹음을 지운다.
- 응답은 늘 200 에 `{result, text?, detail?}` 다(인증·형식 오류만 4xx): `ok`, `empty`(말소리를 못 들었다), `busy`,
  `error`(detail 은 명령의 마지막 오류 줄).
- 서버 로그(journald)는 «받아쓰기 로그인 N KB 1.9초: ok (M자)» 한 줄이고 글은 싣지 않는다. 명령이 계약을 어겨 JSON 이 아닌
  것을 내면 그 내용도 싣지 않는다(바이트 수만) — 받아쓴 맨 글일 수 있다.
- **받아쓴 글은 받아쓰기 기록에 남긴다**(`--dictation-log`, 기본 `~/.config/mux/dictation-log.jsonl`, 0600). 처음 설계는
  글을 어디에도 남기지 않았는데, 폰에서 «음성처리가 이상할 때가 많다» 고 했을 때 서버 로그의 크기·글자 수만으로는 무엇이
  잘못됐는지 알 수 없었다 — 사용자가 «녹음 파일까지는 남기지 않아도 되는데 변환된 문자는 로그에 남겨서 나중에라도 확인할
  수 있게» 로 정했다(2026-11-17). 녹음은 여전히 남기지 않는다. 한 줄이 받아쓰기 한 번이다:
  `{"at", "login", "type"(녹음 형식), "bytes", "took"(초), "audio"(녹음 길이), "speech"(VAD 가 말소리로 본 길이), "result",
  "heard"(Whisper 가 낸 그대로), "text"(바꿔 쓰기 뒤 — 폰에 간 글), "error"}`. `audio` 와 `speech` 의 차이가 크면 VAD 가 말을
  잘라냈을 수 있고, `heard` 와 `text` 를 견주면 용어 파일의 바꿔 쓰기가 무엇을 했는지 보인다. 폰이 끊은 받아쓰기(`error`,
  context canceled)도 남는다. 4MB 를 넘으면 `.1` 로 하나만 넘긴다. 서버 로그와 따로 둔 이유: journald 는 다른 프로세스가
  넘치면 줄을 버리고(11-17 tracker 폭주 때 mux-serve 로그가 버려졌다), 글만 골라 지울 수 없다. 제로값(빈 경로)은 «쓰지
  않음» 이라 `go test ./serve` 는 개발자의 `~/.config/mux` 에 닿지 않는다. 보기: `jq -r '[.at, .result, .audio, .speech,
  .text] | @tsv' ~/.config/mux/dictation-log.jsonl`. **보낸 글(`/api/prompt`)은 여전히 어디에도 남기지 않는다** — 프롬프트는
  붙여 넣은 무엇이든 담고, 이 기록은 말한 것만 담는다.

**폰.**

- [말하기] → «녹음 중 0:12» 와 소리 크기 막대(`AnalyserNode` — 들리고 있는지 보인다). [그만] 또는 2분에 끝난다.
  끝나면 «받아쓰는 중…», 글이 오면 입력칸의 글 뒤에 붙인다.
- 끝나는 즉시 마이크 트랙을 멈춘다 — iPhone 의 마이크 표시가 남지 않게. 페이지가 가려지면 거기까지 녹음한 것을 받아쓴다
  (말한 것을 버리지 않는다).
- 받아쓰기가 실패하면 녹음을 들고 있다가 [다시 받아쓰기] 를 띄운다 — 다시 말하지 않아도 된다. 다음 녹음을 시작하면 버린다.
  `empty` 는 «말소리를 듣지 못했습니다». 답을 받지 못했어도 Claude 에게는 아무것도 가지 않았으니 그렇게 말한다.
- 서버가 녹음을 거절하면(4xx) [다시 받아쓰기] 를 띄우지 않는다 — 다시 올려도 같다. 404 는 위 «켜고 끄기» 처럼 물러선다.
- 받아쓰는 동안 마이크 버튼은 꺼진다. [보내기]·답하기는 정말 보낼 때 녹음·받아쓰기를 거둔다(올리는 중이면 fetch 를 끊는다 —
  서버가 명령을 죽인다). 늦게 온 글이 보낸 뒤의 입력칸에 붙지 않는다. 700자 넘김처럼 보내기가 막히면 거두지 않는다 — 아직
  받아쓰지 않은 녹음을 버리지 않게.

## 음성 — 브라우저 받아쓰기 (`--whisper` 가 없을 때)

- 브라우저 `SpeechRecognition`(`webkitSpeechRecognition` 포함), `lang = "ko-KR"`, `interimResults = true`.
- **듣는 동안 받아쓴 글을 입력줄 위에 크게(21px) 보여 준다**(«듣는 중» 상자). 확정된 낱말은 진하게, 아직
  바뀔 수 있는 중간 결과는 흐리게. 듣기가 끝나면 상자가 접히고 글이 입력칸(17px)에 들어간다. 사용자 요청
  «첫 화면에서 음성으로 했을 때 문자로 표기되는 부분» 의 답이다 — 1판은 보내기 창 안의 작은 한 줄이었다.
- **자동으로 보내지 않는다** — 사용자가 입력칸에서 고친 뒤 [보내기]. 보낼 곳을 고르기 전에도 말할 수 있고,
  그때는 «보낼 곳을 고르세요» 가 경고색으로 뜬다.
- [그만] 을 누른 순간의 중간 결과도 입력칸에 넣는다 — iOS 는 멈추면 확정 결과 없이 끝날 때가 있다.
- **iPhone Safari 의 버릇에 맞춘다**(2026-11-17, 사용자의 폰. 처음 판은 «음성 인식이 안 될 때가 많음» — 증상은 «말하는
  도중 끊김», «말해도 글이 안 들어감»). 처음 판은 한 번 말하기(`continuous = false`)라 말을 잠깐 멈추면 끝났고, 결과가 올
  때마다 마지막 결과로 글을 덮어써서 Safari 가 멈춘 뒤 앞 글을 지우고 새로 적거나 끝에 빈 결과를 보내면 들은 말을 잃었다.
  Safari 의 계속 듣기는 앞 결과를 겹쳐 보내고(«안녕» 다음 «안녕 하세요», 같은 확정 두 번), «그만» 뒤에 끝 신호(`onend`)를
  안 보낼 때가 있다는 보고가 있다(WebKit 버그·개발자 포럼, 사용자 확인 전). 그래서:
  - 계속 듣기로 듣고, 인식기가 저절로 끝나면 들은 글을 지닌 채 **새 인식기로 이어 듣는다**. 끝나는 것은 [그만], 2분 상한,
    새 글 없이 이어 듣기 5번, 고칠 수 없는 오류(`not-allowed`·`service-not-allowed`·`audio-capture`) 때뿐이다.
  - 결과는 받을 때마다 처음부터 다시 엮고, 겹친 결과는 낱말(대소문자·문장부호 무시)로 걸러 긴 쪽 하나만 남긴다(`joinResults`).
    빈 결과는 버리고, 확정 아닌 결과가 앞부분만 남기면 긴 쪽을 지키고, 첫 낱말부터 다른 절반 아래 길이의 글이 오면 Safari 가
    새로 적기 시작한 것으로 보고 앞 글을 따로 모아 둔다(`nextHeard`). **들은 글은 줄지 않는다.**
  - [그만] 뒤 1.5초 안에 끝 신호가 없으면 그때까지 들은 글로 마친다.
  - 글 없이 끝나면 알림이 저절로 접히지 않고, 받은 사건 순서(`start → audiostart → result → end …`)와 오류를 작게 붙인다 —
    폰 화면을 찍어 보내면 무엇이 일어났는지 안다. 받아쓰기가 꺼진 iPhone(`service-not-allowed`)은 설정 경로를 말한다.
  - 확인: Chrome 에서 `webkitSpeechRecognition` 을 가짜로 바꿔 여덟 경우를 돌렸다 — 멈춘 뒤 새로 적기와 빈 확정, 저절로
    끝난 뒤 이어 듣기, 겹친 결과, 끝 신호 없음, 말소리 없음(새 글 없이 6번 듣고 이유 알림), 받아쓰기 꺼짐, 이미 쓴 글 뒤에
    붙이기, 끝난 인식기의 늦은 결과(다음 받아쓰기에 섞이지 않음). 진짜 iPhone 에서의 확인은 사용자가 한다(«실측할 것» 3).
- 지원하지 않는 브라우저는 마이크 버튼을 숨기고 입력칸만 둔다(폰 키보드의 받아쓰기로 된다).
- 마이크는 secure context 에서만 열린다 — `tailscale serve` 의 https 가 그 조건이다. `Permissions-Policy:
  microphone=(self)` 를 보낸다.

## 패스키 로그인 — Muxtap

2026-11-18 사용자 요청: «아이폰 브라우저에서 사용하는 툴의 이름이 필요해 보임», «처음 접속하면 생체인식이나 특정 키로
로그인하는 기능 필요해 보임». 이름은 후보 셋(Muxtap·Cue·mux remote) 중 사용자가 **Muxtap** 을 골랐다 — mux + 탭해서
보낸다, 6자라 홈 화면에서 잘리지 않는다.

**왜 Tailscale 신원만으로 모자란가.** `Tailscale-User-Login` 은 기기가 아니라 계정이다. 같은 계정으로 로그인한 tailnet 의
어느 기기든, 잠금이 풀린 폰을 든 누구든 Claude 에게 글을 칠 수 있었다 — Claude 는 셸 권한이다. 패스키는 그 뒤의 둘째
겹으로 «등록한 이 기기 + 사람 확인(Face ID·보안 키 PIN)» 을 본다. Face ID 와 보안 키(YubiKey 등, iPhone 은 NFC·USB-C)를
한 방식으로 받는다.

```
처음 한 번:  데스크톱 `mux serve enroll` → 코드 1234-5678 (해시만 passkeys-enroll.json, 0600, 10분)
             폰 /login → 코드 → POST /auth/register/begin → Face ID(navigator.credentials.create)
             → POST /auth/register/finish → 공개키를 passkeys.json(0600)에 더함, 코드를 지움, 로그인 쿠키
그다음:      폰 / → (쿠키 없음) 303 /login → [Face ID 로 열기] → /auth/login/begin → Face ID(get)
             → /auth/login/finish → 쿠키 `__Host-muxtap` → / 로
```

되돌리기 쉬운데 되돌리면 안 되는 것(`serve/login_test.go`, 아래 «검증» 의 되돌려 보기 19가지):

- **사람 확인(UV)을 요구한다** — 등록·로그인 모두 `userVerification: required`. 화면을 누르기만 한(UP) 응답은 받지 않는다.
  목적이 «폰을 든 사람이 본인인가» 이기 때문이다.
- **등록은 코드로만, 첫 기기도.** 코드 없이 첫 등록을 받으면 먼저 연 사람이 주인이 된다. 코드는 8자리, 해시로만 파일에,
  10분, 다섯 번 틀리면 서버가 지운다(틀린 횟수는 메모리 — 코드가 바뀌면 0부터). **코드 하나는 패스키 하나** — 등록을 끝낼
  때 «시작할 때 맞힌 그 코드가 아직 살아 있는가» 를 보고 지운다(`take`). 같은 코드로 두 기기가 시작한 경우, 시작한 뒤 새
  코드가 나온 경우, 시작한 뒤 코드 시간이 지난 경우 모두 거절한다. Face ID 를 취소하면 같은 코드로 다시 할 수 있다(맞힌
  것만으로는 지우지 않는다).
- 코드를 해시로 두는 것은 코드가 평문으로 디스크·백업에 남지 않게일 뿐이다. 같은 사용자의 프로세스는 여덟 자리를 모두
  해 볼 수 있지만, 그 프로세스는 `mux serve enroll` 을 직접 돌릴 수도 있다.
- **`mux serve enroll` 은 서버와 말하지 않는다** — `--passkeys` 곁의 `passkeys-enroll.json` 을 쓰고, 서버가 요청마다 읽는다.
  패스키 파일(`passkeys.json`)을 쓰는 것은 서버뿐이다(같은 폴더의 임시 파일 → rename, 0600).
- **깨진 패스키 파일을 빈 것으로 보지 않는다** — 빈 것으로 보고 새로 쓰면 등록한 패스키를 모두 잃는다. 등록·로그인은
  `broken` 이고, 시작 로그가 고치거나 지우라고 말한다.
- **패스키는 요청 Host 의 이름(포트 뺌)에 묶이고, 응답의 origin 은 `https://<Host>` 여야 한다.** Host 는 이미 4번 규칙이
  `.ts.net` 으로 봤다. `ts.net` 은 공개 접미사 목록에 있어(2026-11-18 publicsuffix.org 확인) 다른 tailnet 의 funnel 페이지가
  이 패스키를 쓰지 못한다. 기계 이름이 바뀌면 다시 등록한다.
- **도전값(SessionData)은 서버 메모리에만** 두고 폰에는 id 만 준다. 한 번만 쓰고(꺼내며 지운다), 3분, 시작한 Tailscale
  로그인만 끝낼 수 있다. 16개 상한.
- **로그인 쿠키는 메모리에만**, `__Host-` 접두사·Secure·HttpOnly·SameSite=Strict·Path=/. **30분 동안 요청이 없으면 끝난다**
  (사용자 결정 — 후보는 30분·12시간·30일). 화면이 열려 있으면 2초마다 목록을 읽으니 끊기지 않고, 폰을 잠그면 요청이 멈춰
  세기 시작한다. 쿠키는 그것을 만든 Tailscale 로그인에서만 통한다. 서버를 다시 띄우면 모두 다시 Face ID 다. 32개 상한.
- **서명 횟수가 뒤로 간 자격은 그 뒤로 늘 거절한다**(보안 키 복제 의심, 로그에 «복제 의심» 과 그 자격의 기기·등록 시각).
  거절하기 전에 바뀐 자격을 파일에 쓰므로 의심 표시(`cloneWarning`)가 남고, 라이브러리는 그 표시를 지우지 않는다 — 그
  한 번만 거절하면 복제한 쪽이 더 큰 횟수로 앞서 나가 다시 열린다(독립 검토가 찾았다, 2026-11-18). iPhone 패스키는 늘 0이라
  걸리지 않는다. 로그인할 때마다 바뀐 횟수·플래그를 파일에 다시 쓴다 — 다음 검증이 그 값과 비교한다.
- **로그인 없이 열리는 경로는 이름이 꼭 같은 것뿐**(`publicPaths`: 로그인 화면·login.js·app.css·manifest·아이콘·`/auth/*` 다섯).
  앞머리로 맞추지 않는다. 모두 Tailscale 신원·Host·Origin 검사 뒤다.
- **login.js 는 누르기 전에 도전값을 받아 두고, 누르면 `await` 없이 `navigator.credentials` 를 부른다.** Safari 가 패스키 창을
  사용자 동작 안에서만 여는지, 누른 뒤의 `fetch` 를 지나서도 그 동작이 살아 있는지 재지 못했다(독립 검토의 지적) — 그래서
  그것에 기대지 않는다. 로그인 도전값은 화면을 열 때·다시 보일 때(`visibilitychange`)·90초마다·실패한 뒤 새로 받고, 2분이
  지난 것은 쓰지 않는다(서버 의식 3분). 등록 도전값은 코드 여덟 자리가 다 들어오면 그 코드로 받는다 — 틀린 코드는 넣자마자
  알린다(그 시도도 다섯 번에 든다). 브라우저 시험이 «누른 순간의 첫 호출이 get/create 이고 fetch 가 아니다» 를 본다.
- 로그인 전 `GET /` 는 303 `/login`, 나머지는 401 이다. 401 은 로그에 적지 않는다 — 쉬다 돌아온 폰이 한 번씩 받는 평범한
  답이다. `app.js` 는 401 이면 `/login` 으로 간다.
- **`--passkeys=`(빈 값)이 «꺼짐»** 이다 — 제로값이 꺼짐인 것은 시험이 개발자의 `~/.config/mux` 에 닿지 않게이고(e2e 의
  `startServe` 가 이것으로 끈다), 기본값은 `~/.config/mux/passkeys.json` 이다. 기본 자리를 못 정하면(설정 폴더 없음) 시작하지
  않는다 — 조용히 꺼지지 않게.
- 잃은 기기 끊기: `passkeys.json` 에서 그 항목(`device`·`added` 로 알아본다)을 지우고 서비스를 다시 띄운다(살아 있는 쿠키도
  끊긴다). 모두 지우려면 파일을 지운다 — 다음 접속은 등록 화면이다.
- 홈 화면: `manifest.webmanifest`(`display: standalone`)와 `apple-touch-icon`(180px). 아이콘은 어두운 바탕에 터미널 프롬프트
  «›_» 다. 홈 화면 앱은 Safari 와 쿠키를 따로 가져 처음에 한 번씩 Face ID 를 한다.
- 검증은 `go-webauthn/webauthn` v0.18.2(2026-09-19)에 맡긴다 — 서명 검증 같은 보안 코드를 직접 짜지 않는다(사용자 결정).
  v0.18 이 Go 1.26 을 요구해 `go.mod` 의 `go` 줄이 1.24.2 → 1.26.0 이 됐다(1.24 는 지원이 끝났다, CI 는 `go.mod` 를 읽는다).
  간접 의존성 12개가 늘었고 `golang.org/x/text` 가 0.3.8 → 0.42.0 이 됐다(화면 골든 포함 단위 시험 전부 그대로 통과).

## 보안

`mux serve` 는 사용자 권한으로 Claude 에게 글을 친다. 폰 쪽 신원은 Tailscale 이 붙이는 헤더 하나다.

1. **바인드는 127.0.0.1 만.** `--addr` 가 루프백이 아니면 시작하지 않는다. tailnet·LAN 에 직접 열리지 않는다.
2. **`Tailscale-User-Login` 이 `--allow` 목록과 같을 때만 응답한다.** 헤더가 없으면 403 — 이 기계에서
   127.0.0.1 로 직접 들어온 요청이다. `--allow` 가 비면 시작하지 않는다(«아무나» 는 기본값이 될 수 없다).
3. **`Tailscale-Funnel-Request` 헤더가 있으면 403.** funnel 을 쓰지 않지만, 누가 켜도 인터넷 요청이 닿지 않게.
4. **Host 확인.** 루프백 포트는 이 기계의 브라우저에서도 닿는다. DNS 리바인딩으로 `evil.example` 을
   127.0.0.1 로 바꾸면 그 페이지는 같은 출처로 헤더를 마음대로 붙여 읽을 수 있다. Host 의 이름이 `.ts.net`
   으로 끝나지 않으면 403 이다(`--host-suffix` 로 다른 꼬리를 줄 수 있다). «box.ts.net.evil.example» 처럼 중간에
   `.ts.net` 이 든 이름도 막는다.
5. **POST 는 Origin 이 `https://<Host>` 와 같고 `Content-Type: application/json` 일 때만.** JSON 본문은
   다른 출처에서 사전 요청 없이 보낼 수 없다. 본문은 8KB 로 자른다. 받아쓰기(`/api/transcribe`)만 녹음 형식
   `audio/webm`·`audio/mp4` 를 받는다(10MB) — 이 둘도 CORS 의 단순 요청 형식이 아니다. 단순 요청 형식(`multipart/form-data`·
   `text/plain`·form)은 어느 경로도 받지 않는다(`acceptsBody`).
6. **CSP** `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self';
   frame-ancestors 'none'; base-uri 'none'; form-action 'none'` — 인라인 스크립트·스타일이 없다(테스트가 본다). 다른
   사이트가 iframe 에 넣고 [보내기] 를 누르게 만들 수 없다(`X-Frame-Options: DENY` 도). `Permissions-Policy` 는 마이크만
   열고, 모든 API 응답은 `Cache-Control: no-store`. 보안 헤더(CSP·X-Frame-Options·nosniff·Referrer-Policy·
   Permissions-Policy)는 거절 응답에도 붙는다.
7. 이 기계의 다른 프로세스는 헤더를 위조해 127.0.0.1 로 들어올 수 있다. 같은 사용자의 프로세스라면 이미
   tmux 를 직접 부를 수 있으니 얻는 것이 없다. 이 기계를 다른 사람과 같이 쓰면 이 가정이 깨진다(아래 «버린 것»).
   패스키 로그인이 켜져 있으면 이 경우에도 로그인 쿠키가 있어야 한다.
8. **패스키 로그인**(위 절) — 1~6 을 지난 요청도 살아 있는 로그인 쿠키가 없으면 로그인 화면과 그 재료만 받는다.

## 띄우기 — 443 을 덮지 않는다

요청서의 `tailscale serve 7690` 은 https **443** 에 건다. 이 기계의 443 은 이미 `http://127.0.0.1:7317` 에
매여 있다(2026-11-17 `tailscale serve status`, 지금은 7317 을 듣는 프로세스가 없다). 덮지 않도록 다른 https
포트를 쓴다: `tailscale serve --bg --https=8443 127.0.0.1:7690` → `https://<기계>.<tailnet>.ts.net:8443/`.
끄는 것은 `tailscale serve --https=8443 off`. `mux serve` 는 tailscale 설정을 건드리지 않는다 — 사람이 한 번 건다.

## 실측할 것 (구현 뒤, 폰 실측 전에)

1. `tailscale serve` 가 들어온 `Tailscale-User-*` 헤더를 지우고 자기 값을 넣는가 — curl 로 위조 헤더를
   붙여 tailnet 쪽에서 보낸다. 지우지 않으면 2번 규칙이 무너진다. **2026-11-17 확인(tailscale 1.104.7, 같은 기계에서
   `https://<기계>.ts.net:8443`)**: `Tailscale-User-Login: evil@example.com` 을 붙인 요청이 200 이었고 서버 로그에
   «허용 목록 밖» 거절이 없었다 — 들어온 값을 자기 값으로 덮어쓴다. 다른 기계(폰)에서 한 번 더 본다.
2. 백엔드에 오는 `Host` 가 `…ts.net:8443` 인가(127.0.0.1:7690 으로 바뀌면 4번 규칙을 `X-Forwarded-Host` 로 바꾼다).
   **2026-11-17 확인**: 그대로 온다(기본 요청 200). 127.0.0.1:7690 으로 직접 들어온 요청은 «Host 127.0.0.1:7690» 으로 403.
3. 폰 Safari(iOS)·Chrome(Android)에서 `webkitSpeechRecognition` 이 ko-KR 로 도는가, 권한 대화상자가 뜨는가.
4. 화면 탭에서 넓은 글자 상자로 Claude 의 선·대화상자 테두리가 맞는가. 카드의 글리프(⏳❗✅)가 폰 글꼴에서 같은 폭인가.
5. 길게 누르기가 폰의 글자 선택·문맥 메뉴와 부딪치지 않는가(`user-select: none`, `contextmenu` 막기).
6. 세션 페이지에서 뒤로 가기(Android 뒤로, iOS 왼쪽 가장자리 밀기)가 목록으로 돌아오고, `#s=<세션>` 주소로
   새로 고치면 그 세션에 다시 들어가는가.
8. 패스키: iPhone Safari 에서 `https://<기계>.ts.net:8443` 에 패스키를 등록하고 Face ID 로 여는가, 홈 화면에 추가한 Muxtap
   (standalone)에서도 되는가, 홈 화면의 이름·아이콘, 폰을 잠그고 30분 넘게 둔 뒤 돌아오면 로그인 화면이 뜨는가, iCloud
   키체인으로 동기화된 다른 Apple 기기에서도 그 패스키로 열리는가(등록은 기기마다가 아니라 키체인마다가 된다), 버튼을 누르자마자
   Face ID 창이 뜨는가(뜨지 않고 «취소했거나 시간이 지났습니다» 가 나오면 사용자 동작 문제다).
   **2026-11-18 확인(사용자, 서버 로그)**: iPhone 에서 코드로 등록이 됐고 «이 기기 등록» 을 누르자 Face ID 창이 떴다 — 등록
   쪽(create)은 미리 받은 도전값으로 사용자 동작 안에서 열린다. 저장된 자격은 UV·BE·BS(iCloud 키체인), transports
   `internal`·`hybrid`, 서명 횟수 0, rpID 는 전체 호스트 이름이다. 남은 것: «Face ID 로 열기»(get — 등록 때 받은 쿠키로 들어가
   로그에 아직 «패스키 로그인» 이 없다), 홈 화면 앱, 30분 쉰 뒤, 다른 Apple 기기.
7. 서버 받아쓰기(`--whisper`): iPhone Safari 가 무슨 형식으로 녹음하는가(받아쓰기 기록의 `type`·`bytes`·`audio`), 마이크 권한을 들어올
   때마다 묻는가, 녹음이 끝나면 상태 막대의 마이크 표시가 꺼지는가, 소리 크기 막대가 움직이는가, 화면을 잠갔다 돌아오면
   [다시 받아쓰기] 가 뜨는가, 같은 다섯 문장의 결과.
8. 보관함 되살리기: 실제 보관함(sekihe-2 등)을 폰에서 되살려 같은 대화가 이어지는가, 세션 페이지에서 그 Claude 에게 바로
   보낼 수 있는가, 패널(`mux panel --auto` 훅)이 되살린 세션에도 붙는가.

자체 서명 인증서의 TLS 프록시(신원 헤더를 붙임)를 두고, headless Chrome 157 을 `--ignore-certificate-errors-spki-list` 와
CDP 가상 인증기로 몰아 20가지를 확인했다: 로그인 전 `/` → `/login`, 처음엔 등록 칸만, 탭 제목, 코드 전·틀린 코드에서 등록
버튼 꺼짐과 문구, 맞는 코드에서 켜짐, **누른 순간의 첫 호출이 create·get 이고 fetch 가 아님**(누른 뒤 서버에 먼저 묻도록 바꾼

않음(«취소했거나 시간이 지났습니다»), «새 기기 등록», 실패 뒤 도전값을 다시 받아 버튼이 켜짐, 다시 UV 를 켜면 열림.

## 버린 것 / 2차

- **비밀번호·PIN 로그인** — 서버가 비밀을 가져야 하고, 추측·어깨너머 보기를 따로 막아야 한다. 패스키는 서버에 공개키만 둔다.
- **패스키 검증을 표준 라이브러리로 직접**(ES256 만, 의존성 0) — 사용자가 검증된 라이브러리를 골랐다. 보안 코드는 직접 짜지 않는다.
- **코드 없는 첫 등록** — 먼저 연 사람이 주인이 된다.
- **로그인 쿠키를 디스크에** — 재시작 뒤에도 남지만, 잃은 기기의 쿠키를 끊는 수단이 «다시 띄우기» 다.
- **열자마자 Face ID 창 띄우기** — Safari 가 사용자 동작 없는 `navigator.credentials` 호출을 막는지 재지 않았다. 버튼 하나다.

- **SSE** — 폴링보다 빠르지만 연결을 쥐고 있어야 하고, «클라이언트가 없으면 아무것도 돌지 않는다» 를
  지키려면 연결 수를 세야 한다. 2초면 이 쓰임에 충분하다.
- **유닉스 소켓 바인드** (`tailscale serve unix:/run/user/1000/mux/serve.sock`) — 파일 권한이 다른 사용자와
  브라우저(DNS 리바인딩)를 한 번에 막아 더 단단하다. tailscale 이 유닉스 소켓 백엔드에도 신원 헤더를 붙이는지
  재지 못해 2차로 미뤘다. 재면 4번(Host) 규칙이 필요 없어진다.
- **패널 줄을 그대로 그리기**(1판, `notifyLines` 의 `{session, ansi}`) — 요청서의 방식이었다. 13px 고정 폭 줄이
  폰에서 빽빽해 세션이 서로 구분되지 않았다. 판정 함수만 나눠 쓰고 카드로 그린다.
- **최근 이벤트 로그** — 폰에서는 보지 않는다(사용자). 2판에서 뺐다.
- **따로 여는 보내기 창**(1판) — 음성으로 보내기까지 세 번 눌러야 했다. 첫 화면의 입력줄로 바꿨다.
- **길게 누르기로만 들어가기, 아래에서 올라오는 창**(1·2판) — 길게 누르기는 있는 줄 모르고 iOS 의 글자 선택과
  부딪친다. 창은 뒤로 가기·새로 고침과 맞지 않았다. [›] 와 페이지(`#s=<세션>`)로 바꿨다.
- **회신만 보이는 탭**(1·2판) — 무엇에 대한 회신인지 보이지 않았다. 대화 탭이 보낸 말을 함께 보인다.
- **서버 쪽 ANSI→HTML** — 서버가 HTML 을 만들면 이스케이프를 서버에서 책임져야 한다. 화면 탭 하나뿐이니
  클라이언트가 한다.
- **세션 이름·Claude 이름으로 지목** — pane id + pid 로 지목한다. 이름은 같은 것이 여럿일 수 있다(agent-api.md).
- **번호 없는 메뉴(폴더 신뢰 등)에 답하기** — 숫자키로 고를 수 없고 화살표만 된다. 쓰임이 드물어 화면 탭으로 본다.
