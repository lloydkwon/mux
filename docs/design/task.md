# `mux task` — 작업마다 짧은 워커 세션 (`start` · `ls` · `done`)

> 관련 코드: tmux/task.go(목록·상태), tmux/task_start.go, tmux/task_conversation.go(이어 갈 대화), tmux/task_done.go, cmd/mux/task.go, ui/notify.go(`taskMarker`),
> tmux/claude_status.go(`UserName`), tmux/claude_work.go(`WithClaudeWork`), tmux/eventlog.go(`MergeEvents`),
> e2e/task_e2e_test.go, e2e/task_resurrect_e2e_test.go, scripts/tmux-assumptions.sh 21절
>
> 2026-11-25 에 설계하고 사용자 승인을 받아 만들었다(1단계). 실측은 모두 2026-11-25, Claude Code 2.1.332 · tmux 3.8 · git 2.56.1, 스크래치 저장소와 격리 서버에서 했다.

## 무엇이고 무엇이 아닌가

**작업 하나 = worktree 하나 = `t-<id>` 세션 하나 = Claude 하나.** 오래 가는 세션은 그대로 두고, 생겼다 사라지는
워커 세션을 더한다. 1단계는 시작·목록·정리 셋이다.

```sh
T=$(mux task start m123 --repo ~/dev/projects/my/mux --title "로그인 오류" --prompt "Mantis #123 을 읽고 진행")
mux agent wait t-m123 --after "$T"
mux task ls
mux task done m123
```

하지 않는 것(요청서 «범위 밖»): 리뷰 세션, CI·MR 되돌리기, 보드, 이슈 내용 가져오기, 브랜치 삭제. 네트워크 호출도 없다.

## worktree 는 mux 가 만든다 — `claude --worktree` 를 쓰지 않는다

`claude --worktree t-x` 를 실행해 잰 것:

| 물음 | 잰 결과 |
|---|---|
| 경로 | `<저장소>/.claude/worktrees/t-x`. 원본에서 `git status` 에 `?? .claude/` 로 보인다 |
| 브랜치 | `worktree-t-x` |
| 시작점 | 원격이 있으면 로컬이 아는 `origin/HEAD`(지금 checkout 이 아니다). 없으면 HEAD |
| 같은 이름으로 다시 | 그 worktree 를 다시 연다. `--continue` 도 함께 된다 |
| 첫 프롬프트 인자 | 된다 |
| 신뢰 안 된 저장소 | 종료 코드 1 («…dialog, then retry with --worktree») |
| 잠금 | `git worktree lock` 을 건다. 세션을 `kill-session` 해도 남아 `git worktree remove` 가 128 로 거절한다 |
| `/exit` | **변경이 없으면 worktree 와 브랜치를 지운다.** 변경이 있으면 «Keep / Remove» 를 묻는다 |
| 셸 pane 의 폴더 | Claude 만 worktree 로 옮긴다. 세션의 시작 폴더는 원본이라 새 pane 은 원본에서 열린다 |

mux 가 `git worktree add` 로 만들고 그 안에서 Claude 를 여는 쪽을 고른다. 이유:

- **`/exit` 가 브랜치를 지운다.** «브랜치는 지우지 않는다» 와 어긋나고, 정리의 주인이 둘이 된다.
- **시작점이 틀린다.** water_ai 는 `release/next` 에서 일하는데 `origin/HEAD` 는 `origin/master` 다.
- 잠금과 폴더 문제가 없다. 직접 만든 worktree 에서 Claude 는 잠금을 걸지 않고, `/exit` 뒤에도 worktree 와 브랜치가 남는다.
- 이미 있는 New worktree 행([worktree.md](worktree.md))과 자리·git 규칙을 함께 쓴다.

신뢰 대화상자는 어느 쪽에서도 문제가 되지 않는다. 신뢰한 저장소의 linked worktree 는 저장소 옆에 있어도 묻지 않는다.
자동 메모리도 원본 저장소의 것을 함께 쓴다.

잃는 것 둘: `.worktreeinclude` 복사가 없다(sekihe-php 에 그 파일이 있다). `.env`·`node_modules` 처럼 무시된 파일은
새 worktree 에 없다.

### 자리와 이름

| | 값 |
|---|---|
| 세션 | `t-<id>` |
| 폴더 | `<원본의 부모>/<원본 이름>-t-<id>` — New worktree 와 같은 규칙 |
| 브랜치 | `t-<id>`. 시작점은 `--repo` 폴더의 HEAD 이고, 커밋을 stderr 에 알린다 |
| id | `^[a-z0-9][a-z0-9-]*$`, 40자 이하. `-` 로 시작하면 옵션으로 읽힌다 |

- **작업은 폴더 경로로 알아본다.** Claude 가 worktree 안에서 브랜치 이름을 바꿔도 같은 작업이다.
- **브랜치 `t-<id>` 가 이미 있으면(로컬·원격) start 를 거절한다.** `done` 이 브랜치를 남기므로, 조용히 다시 쓰면 이미 머지된
  브랜치 위에 새 일이 쌓인다. 이어서 하려면 사람이 `git worktree add <자리> t-<id>` 를 한 뒤 `task start` 를 부른다.
- **`@project_dir` 을 달지 않는다.** 달면 패널 자동 삽입이 물러난다(worktree.md).
- **이름이 정확히 `t-<id>` 여야 한다.** `CreateSessionWithCommand` 는 겹치면 `-2` 를 붙이므로 쓰지 않는다.
- **세션을 지목할 때는 늘 `=t-<id>` 다.** 맨 이름은 `t-m1` 이 이미 없으면 접두사로 `t-m12` 를 죽인다(tmux-assumptions 17절). 이 이름
  규칙에서는 늘 생기는 짝이다. TUI 의 `x`(닫기)·이름 바꾸기·메모도 같은 날 정확히 지목하게 고쳤다(`exactSession`,
  `exactSessionOption`) — 확인 창이 떠 있는 사이 `done` 이 그 세션을 닫으면 `y` 가 이웃 작업을 닫았다. 이름에 `.`·`:`·`$` 가 든
  세션은 tmux 3.8 에서 맨 이름으로도 닫거나 이름을 바꿀 수 없어 잃는 것이 없고, `:` 가 든 이름의 메모만 오류가 된다(잼).

### 리뷰어 이름 `r-<id>` — 2단계를 위한 예약

2단계의 리뷰어는 워커와 **같은 worktree** 에서 돈다. mux 는 아직 리뷰어를 만들지 않고 이름만 예약한다(`ReviewID`,
`ReviewSessionName`, 정규식으로는 `^r-[a-z0-9][a-z0-9-]{0,39}$`). 리뷰어는 재부팅 복구나 재시작 때 예전 대화로 돌아가지 않고 늘 새
대화로 시작해야 해서(OpenRig 시험에서는 기본값이 이전 대화에 이어 붙였다), 복구 쪽이 이 이름으로 가른다.

- **이름으로는 섞이지 않는다.** `TaskID` 는 `t-` 만 읽는다. `t-r-1` 은 id 가 `r-1` 인 워커다.
- **대화로 섞인다 — 그래서 거른다.** 기록 폴더는 worktree 하나에 하나라, 거르기 전에는 세션이 닫힌 뒤 `start` 가 워커 대신 리뷰어의
  대화를 이어 열고, 리뷰어가 받은 글을 «첫 프롬프트를 보냈다» 로 셌다(관찰). 이름(`custom-title`)이 한 번이라도 `r-<id>` 였던 대화는
  그 작업의 워커 대화가 아니다(`taskConversation.review`). `--title r-<id>` 는 거절한다.
- **`done` 은 리뷰어가 열고 있으면 어떤 상태든 거절하고(막혀 있으면 3, 아니면 5) 무엇을 닫을지 말한다.** 함께 닫을지는 2단계에서
  정한다.
- **띄우는 모양(2단계의 규칙):** `claude --session-id <새 UUID> --name=r-<id>; exec "$SHELL"`. 이름에 공백과 메타문자가 없어 복구가 다시
  쳐도 안전하고, 첫 줄부터 기록에 이름이 남는다. 실제 resurrect 로 잰 것: 대화가 있었으면 다시 친 줄이 «already in use» 로 끝나 셸만
  남고, 턴이 없었으면 새 대화가 열린다. 옛 대화로 돌아간 경우는 없었다. `--resume` 을 쓰면 안 된다.
- 저장본에서 `r-*` 를 빼는 훅(`@resurrect-hook-post-save-layout`)은 두지 않았다. 그 옵션은 자리가 하나뿐이고 2026-11-25 현재 OpenRig
  시험 줄이 쓰고 있다. 빼기로 하면 그 줄과 같은 모양의 `sed` 에 위 정규식을 쓴다.

### 볼 저장소 — `~/.config/mux/task-repos.txt`

한 줄에 절대 경로 하나, `~` 와 `#` 주석을 받는다. 상태가 아니라 설정이다. `preferences.json` 에 넣지 않는 것은 TUI 가
통째로 다시 쓰기 때문이다(park.md).

- `ls`·`done` 과 중복 검사가 보는 곳: 이 파일 ∪ `--repo` ∪ 지금 폴더의 저장소 ∪ 살아 있는 `t-*` 세션의 저장소
- `start` 의 저장소: `--repo`, 없으면 지금 폴더의 저장소(linked worktree 면 그 원본), 그것도 없으면 오류
- 파일에 없는 저장소로 start 하면 만들되 경고한다. 세션이 죽은 뒤에는 `ls` 가 찾지 못하기 때문이다.

## 실행 모양 — 지금 복구 방식이 그대로 되살리게

재부팅 복구는 tmux-resurrect·continuum 이 맡고, mux 는 새 복구 로직을 만들지 않는다. 그 대신 **복구가 알아보는 모양으로
띄운다.** resurrect 가 하는 일은 둘이다.

- 저장: pane 프로세스의 **자식** 명령줄을 적는다(`ps.sh`).
- 복원: 그 줄이 `@resurrect-processes` 의 `claude` 로 시작하면, pane 폴더의 셸에 **인용 없이 그대로** 친다.

거기서 세 가지가 나온다.

1. **Claude 는 셸의 자식이어야 한다.** pane 명령이 Claude 자신이면 그 자식(`agent-desktop mcp`)이 저장된다. 지금 실 서버의
   `infra-monitor`·`water_ai2` 가 그래서 복구되지 않는다.
2. **사람이 쓴 글을 명령줄에 두지 않는다.** `-n "사람이 준 제목"` 은 인용이 풀려 `제목` 이 프롬프트로 들어가고, 제목의
   `$(…)`·`;` 는 셸이 실행한다. 제목은 이슈에서 온 글일 수 있다.
3. **같은 줄을 다시 쳤을 때 같은 대화로 이어져야 한다.** 처음부터 그런 명령은 없다.

| 명령 | 대화가 없을 때 | 다시 칠 때 |
|---|---|---|
| `claude` | 새 대화 | 또 새 대화 |
| `claude --session-id U` | 새 대화 | «already in use», 종료 코드 1 |
| `claude --continue` | 종료 코드 1 | 이어진다 |
| `claude --resume U` | 종료 코드 1 | 이어진다 |

**그래서 씨앗 대화를 먼저 만든다.**

```sh
claude -p --session-id U --setting-sources "" --strict-mcp-config --tools "" '/rename <제목>'
```

모델을 부르지 않는다(`num_turns` 0, `total_cost_usd` 0, 0.26초). 이렇게 만든 대화는 사람 턴이 없어도 `--resume U` 로 열리고,
제목은 `nameSource: user` 로 남는다. `$(x) ; "…"` 가 든 제목도 글자 그대로 들어갔다(입력창으로 친 `/rename` 으로 잰 것). 제목이
없으면 `t-<id>` 로 둔다. 훅과 CLAUDE.md 가 돌지 않게 `--setting-sources ""`, 환경에서 `TMUX`·`TMUX_PANE` 을 뺀다
(`runWorkTitleModel` 과 같은 이유). 러너를 거치지 않는 호출이 하나 늘고, 시험은 함수 변수를 바꾼다.

세션은 이렇게 연다. 문자열에 들어가는 변수는 UUID 뿐이다.

```sh
tmux new-session -d -s t-<id> -c <worktree> -x 120 -y 50 'claude --resume U; exec "$SHELL"'
```

- Claude 를 끝내면 worktree 폴더의 셸이 남는다. 요청서의 «셸 pane 폴더를 worktree 로» 가 이것으로 된다.
- 폭은 120 이다. 140 이상이면 `after-new-session` 이 아무도 안 보는 세션에 패널을 붙인다. 80x24 에서도 한글 653자
  프롬프트는 들어갔다.
- `claude` 는 바깥 클라이언트의 PATH 에서 찾는다. 서버 PATH 에 `~/.local/bin` 이 없어도 `new-session` 은 부른 쪽의 PATH 를
  넘긴다(tmux-assumptions 20절). 부른 쪽의 PATH 에도 없으면 설치 스크립트가 두는 `~/.local/bin` 을 명령 앞에 붙인다. 이름은
  `claude` 그대로다 — 절대 경로면 복구가 알아보지 못한다.
- 세션을 만들기 전에 초 경계를 기다린다(`waitForNextSecond` — claude-mode.md 의 이유). 그동안 `task-session.lock` 을 쥔다. 잠금이
  없으면 함께 부른 start 둘을 초 경계가 오히려 같은 초에 세운다.
- **서버를 띄우지 않는다.** 서버가 없으면 `start` 는 1 로 끝난다. 빈 서버가 뜨면 tmux 설정이 저장된 세션 복원을 시작하고, `TMUX_TMPDIR`
  없이 부른 것이면 둘째 서버에 실제 세션과 Claude 가 한 벌 더 뜬다. `mux new` 처럼 `restoreSavedSessions` 를 부르던 안은 검토에서 이
  길이 나와 버렸다. 소켓만 잃은 서버는 되살린다(`ReviveServer`). 기억(`RememberServer`)은 하지 않는다 — 다른 서버의 pane 에서 부른
  조회가 기억을 바꾸면 그 뒤의 보호가 사라진다.

### 복구 왕복을 잰 결과

실제 resurrect 스크립트를 격리 서버에 얹고, 사용자의 설정과 같은 `@resurrect-processes` 로 했다.

| 확인 | 결과 |
|---|---|
| 작업 폴더 | `t-m1`·`t-m12` 둘 다 worktree 로 돌아왔다 |
| 대화 | 같은 대화, 같은 제목으로 이어졌다 |
| 접두사인 이름 | 섞이지 않았다(저장본이 이름순이라 `t-m1` 이 먼저) |
| 만든 직후의 저장 | `session-created` 저장 5번에 5번 모두 명령줄이 들어 있었다 |
| 지운 뒤 저장이 없으면 | **되살아난다.** 폴더가 없어 홈에서 열리고, `claude --resume` 이 홈의 신뢰 대화상자를 띄웠다 |
| 지운 뒤 저장하면 | `last` 에서 빠진다 |
| 시간(셸만) | 세션 5 / 20 / 40: 저장 0.23 / 0.74 / 1.47초, 복원 0.22 / 0.52 / 1.03초 |
| 메모리 | Claude 하나에 자식까지 190~450MB. 열 개가 함께 돌아오면 최대 4.5GB 쯤이다(이 기계 60GB) |

**`done` 은 지운 뒤 저장을 한 번 부른다.** `@resurrect-save-script-path` 가 있으면 `run-shell` 로 부른다. 못 부르거나 실패하면 경고만
한다(플러그인을 쓰지 않으면 말이 없다). 규칙은 사용자의 `session-created` 훅과 같다 — 같은 잠금(`<resurrect 폴더>/.save.lock`),
저장 뒤 1초 더 쥐기, 서버가 뜬 지 30초 뒤부터. 저장본 이름이 초 단위라 같은 초의 둘째 저장은 `last` 가 가리키는 파일을 지우고(사용자가
격리 서버 10회로 잰 것: 그대로 10, 잠금만 2, 잠금 + 1초 0), 복원 중의 저장은 일부 목록으로 덮는다. tmux.conf 가 `session-closed` 훅을 쓰지 않는 이유(종료 때 세션이 하나씩 죽으며 빈 저장본을 남긴다)는
사람이 친 `done` 에는 해당하지 않는다. 그냥 두면 다음 15분 저장 전에 재부팅했을 때 지운 작업이 돌아온다.

한계: 대화 안에서 `/clear` 를 하면 대화 id 가 바뀌지만 명령줄은 그대로라, 재부팅 뒤에는 `/clear` 전의 대화로 돌아온다(2.1.332 에서
재 본 것: `/clear` 뒤 새 대화에 프롬프트를 보냈어도 같은 `--resume U` 는 U 를 연다). 지금 세션들도 같다. `task start` 로 다시 열 때는 그
폴더에서 가장 나중에 쓰인 대화다. `x` 나 `kill-session` 으로 닫은 세션은 저장을 부르지 않으므로 15분 안의 재부팅에 돌아올 수 있다. worktree 가
남아 있어 그때는 정상 작업이다.

## `start`

`--prompt`·`--prompt-file` 검사(`ValidatePromptText`)와 id 검사를 **무엇이든 만들기 전에** 한다. id 마다 `flock` 을 잡는다. 둘이
함께 부르면 뒤의 것이 «worktree 는 있고 세션은 없음» 으로 읽어 프롬프트 없이 열고, 앞의 것은 이름이 겹쳐 실패한다.

| 세션 | worktree | 하는 일 |
|---|---|---|
| 없음 | 없음 | worktree → 씨앗 → 세션 → 준비 대기 → `PromptAgent`. stdout 에 토큰 |
| 없음 | 있음 | 그 폴더의 가장 최근 대화를 `claude --resume <id>` 로 열고 끝. 프롬프트를 보내지 않는다 |
| 있음 | 있음 | 아무것도 하지 않고 알린다(0). Claude 가 꺼져 있으면 그 pane 에서 칠 명령을 알려 준다 |
| 있음 | 없음 | 아무것도 하지 않고 알린다(1 — 이상 상태) |
| 다른 폴더에서 열림 | 있음 | 아무것도 하지 않고 알린다(1). 이름만 같은 사람의 세션이다(`session_path` 로 가른다) |
| 없음 | 있음, 잠김 | 아무것도 하지 않고 알린다(1). 만들다 끊긴 worktree 는 git 이 잠근 채 남긴다 |

- **다른 저장소 안에서 부르면 잇지 않는다.** `--repo` 가 없으면 지금 폴더의 저장소를 말하는 것이다. 그 저장소가 작업의 저장소와 다르면
  1 이다 — 엉뚱한 저장소의 Claude 에게 프롬프트를 보내게 된다. 저장소 밖에서 부르면 설정에서 찾은 하나를 잇는다.
- **대화 고르기.** 그 폴더의 기록(`~/.claude/projects/<폴더>/`) 중 worktree 의 `.git` 파일보다 새것에서 가장 최근 것이다.
  더 오래된 것은 같은 id 로 했던 지난 작업의 기록이다. 이름도 사람 턴도 없는 기록(worktree 안에서 돈 `claude -p`)은 대화로 보지
  않고, 대화 id 모양이 아닌 파일 이름은 셸 명령에 들어가므로 버린다. 폴더 이름은 Claude 의 규칙을 따른다(`projectDirName`) —
  200자를 넘으면 잘라 «-해시» 를 붙이고 이모지는 두 글자로 센다(잼). 못 찾으면 프롬프트를 다시 보내게 되고, 잘린 이름은 이웃 작업과
  같을 수 있어 그때는 기록의 `cwd` 로 가른다. 그 대화를 다른 Claude 가 열고 있으면(herdr 등) 열지 않는다
  — 둘이 한 기록에 쓰게 된다.
- **첫 프롬프트를 이미 보냈는가.** 그 worktree 의 **어느 대화에든** 사람 턴(`origin.kind == "human"`)이 있으면 보냈다. 가장 최근
  것만 보면 `/clear` 뒤의 빈 대화를 «안 보냄» 으로 읽어 다시 보낸다. worktree 를 만들다 죽어 대화가 없거나 사람 턴이 하나도 없으면
  아직 안 보낸 것이다. **이때는 프롬프트를 보낸다** — «다시» 가 아니고, 안 보내면 오케스트레이터가
  start 를 다시 불러도 빈 워커만 남는다. 읽지 못한 기록은 «없음» 이 아니라 오류고, 만든 지 하루가 넘은 worktree 에 보낸 기록이 없으면
  지워진 것일 수 있어 보내지 않고 알린다. 씨앗을 만든 뒤에는 다음 start 가 찾는 길로 찾아지는지 확인한다.
- **준비.** 이 세션의 Claude 가 `Agents()` 에 idle 로 오르고 입력창이 보이는 상태가 **1초 이어질 때까지** 60초. 처음 보이는 것은
  0.33초 뒤였지만, 시작 훅이 도는 동안 친 글은 사라질 수 있다. 상태가 `blocked` 면 기다리지 않고 3, 상태 파일조차 없는 신뢰
  대화상자면 시간이 다 되어 4 다. 어느 쪽이든 아무것도 보내지 않고 세션은 그대로 둔다.
- **보내기.** `PromptAgent` 를 한 번만 부른다. 5 를 보고 다시 부르면 사람의 초안이 있는 입력창에 치고 지우기를 되풀이하게
  된다. 실패하면 그 코드로 끝내고, 그 뒤에는 `mux agent prompt t-<id>` 로 보낸다(세션이 이미 있으므로 start 는 아무것도 하지
  않는다).
- **`--prompt-file`.** 보낼 때에만 읽는다 — 시작한 뒤 파일을 지우고 같은 명령을 다시 불러도 아무 변화가 없다. 한 줄·700자 이하면 그 글을 보낸다. 길거나 여러 줄이면 `<절대 경로> 를 읽고 그대로 진행해` 를 보낸다
  (agent-api.md «긴 본문은 파일에 쓰고 경로를 보낸다»). 폴더 밖 파일 읽기는 이 기계의 기본 권한 모드(auto)에서 묻지 않고 됐다.
- 중간에 실패하면 만든 것을 되돌리지 않는다. 다시 부르면 위 표의 다음 칸에서 이어진다. 프롬프트가 나갔는지 모르는 세션을
  지우는 쪽이 더 나쁘다.
- 권한 모드 옵션은 넘기지 않는다. 사용자의 설정이 정한다.

### 제목

`--title` 은 씨앗의 `/rename` 으로 들어가 대화 기록에 남는다. 그래서 재부팅·이어 열기 뒤에도 따라오고 상태 파일이 필요 없다.
패널은 **`t-*` 세션이고, 이름을 사람이 정했고(`nameSource: user`), 그 이름이 `t-<id>` 가 아닐 때** 세션 아래 줄에 그 이름을 쓰고
Haiku 를 부르지 않는다. 나머지는 지금 그대로다. `t-*` 밖의 세션은 바뀌지 않는다(panel.md «대화 이름으로 물러서지 않는다»).

`@mux_note` 를 쓰지 않은 이유: 사람의 메모 칸이고, 서버와 함께 사라진다.

## `ls`

| 상태 | 뜻 | JSON `state` |
|---|---|---|
| ⏳ ❗ ✅ (셸 배지 포함) | Claude 의 상태. 여럿이면 급한 쪽 | `working` `blocked` `idle` `shell` `unknown` |
| `Claude 없음` | 세션과 worktree 는 있는데 Claude 가 꺼졌다 | `no-claude` |
| `세션 없음` | worktree 만 있다. `task start` 로 다시 연다 | `no-session` |
| `워크트리 없음` | 세션만 있다 (이상) | `no-worktree` |

`Claude 없음` 은 요청서에 없는 상태다. Claude 를 끝내면 셸이 남는 모양이라 필요하다.

`--json` 은 배열이고 필드는 고정이다. 빈 목록도 `[]` 다.

| 필드 | 값 |
|---|---|
| `id` | 작업 id |
| `repo` | 원본 작업 트리의 절대 경로 |
| `worktree` | 폴더, 없으면 `""` |
| `branch` | 지금 체크아웃된 브랜치, detached 면 `""` |
| `session` | `t-<id>`, 없으면 `""` |
| `pane` | Claude 의 pane, 없으면 `""` |
| `sessionId` | Claude 대화 id, 모르면 `""` |
| `state` | 위 표 |
| `since` | 상태 시작 시각(unix ms), 모르면 0 |
| `commits` | 시작점 뒤의 커밋 수, 모르면 -1. 시작점은 그 worktree 의 HEAD reflog 첫 줄이다(브랜치 이름을 바꿔도 남는다. reflog 가 만료되면 실제보다 작게 나온다) |
| `title` | 사람이 준 제목 → 저장된 Haiku 제목 → `""`. 여기서 모델을 부르지 않는다 |

`commits` 는 «✅ idle 인데 커밋 0» 을 알아보라고 있다 — 관문 카드 앞에서 멈춘 워커가 그 모양이다(아래 «전역 규칙을 물려받는 워커»).

git 을 읽지 못한 저장소는 stderr 에 알리고 나머지를 낸 뒤 1 로 끝난다. 사람이 부르는 명령이라 TTL 캐시는 두지 않는다.

## `done`

| 순서 | 확인 | `--force` |
|---|---|---|
| 1 | 세션이 이 작업의 폴더에서 열렸고(worktree 가 안 보이면 그 폴더가 사라졌을 때만), 이 명령을 그 세션 안에서 부르지 않았다 — 안에서 닫으면 자기도 죽어 worktree 가 남는다 | 못 넘는다 |
| 2 | 그 세션이나 worktree 폴더에서 도는 Claude 가 모두 idle 이다(`blocked` 는 3, 나머지는 5). 세션이 이미 없으면 거기서 돌던 Claude 가 끝나기를 10초까지 기다린 뒤에 본다 | 못 넘는다 |
| 3 | worktree 가 잠기지 않았고, 커밋 안 된 변경이 없다(추적 안 된 파일 포함) | 못 넘는다 |
| 4 | HEAD 의 커밋을 가리키는 ref 가 있다(detached 의 떠 있는 커밋이 아니다) | 못 넘는다 |
| 5 | 푸시 안 된 커밋이 없다 | 넘는다 |
| 6 | 1·2 를 새로 읽어 다시 본 뒤 `kill-session -t =t-<id>`. Claude 가 끝나기를 10초까지 기다리고, 안 끝나면 worktree 를 남긴다(5) | |
| 7 | 3·4 를 다시 본 뒤 `git worktree remove`. git 에 `--force` 는 절대 주지 않는다 | |
| 8 | resurrect 저장 한 번 | |

- **2 는 세션 밖의 Claude 도 본다.** 같은 폴더를 herdr 나 다른 세션에서 열어 두었으면 idle 이어도 거절한다 — 발밑의 폴더가 사라진다.
- **세션을 막 닫고 부른 `done` 은 기다린다.** `kill-session` 이 돌아와도 Claude 는 아직 살아 있다(진짜 Claude 는 끝낼 때 훅이 돈다).
  기다리지 않으면 5 다. 작업 세션이 없고, 그 폴더의 Claude 가 어느 pane 에도 살지 않을 때만 10초까지 기다린다(start 가 닫힌 대화를 다시
  열 때와 같은 한도). 닫힐 때의 상태가 파일에 남으므로 idle 이 아니어도 기다린다. 안 끝나면 5(막힌 채면 3)로 «방금 닫은 세션이면 몇 초 뒤
  다시» 를 알린다. 다른 tmux 서버나 herdr 의 Claude 는 밖에서 구별되지 않아 그때도 10초를 기다렸다가 거절한다. 리뷰어처럼 pane 에 사는 것은
  끝나는 중이 아니므로 바로 거절한다. 기다리는 사이 세션이 새로 열렸으면 닫지 않고 1 이다.
- **좀비는 끝난 것이다**(`processAlive`). 끝났는데 부모가 거두지 않은 프로세스는 signal 0 을 받고 `/proc` 에도 시작 시각째 남는다. PID 1 이
  고아를 거두지 않는 컨테이너(`docker run` 에 `--init` 없이 시험을 바로 띄운 것)에서는 닫은 지 1ms 만에 좀비가 되어 15초 뒤에도 그대로였고,
  `done`·`start` 가 «아직 살아 있다» 로 거절했다(tmux 3.4 컨테이너에서 작업 e2e 다섯 개 실패, 기다리기만 해서는 그대로 실패 — 2026-11-25 잰 것).
- **«세션 없음» 을 쉽게 믿지 않는다.** 믿으면 살아 있는 세션을 두고 worktree 를 지운다. 목록은 `tmux -u` 와 `#{q:session_name}` 으로
  읽는다 — UTF-8 로캘이 아닌 곳(cron, 원격 ssh 명령)에서 `-u` 없는 tmux 는 탭과 한글을 `_` 로 바꿔, 처음 짠 코드는 모든 세션을
  «없음» 으로 읽었다(검토에서 재현). 서버에 닿지 못했는데 기억해 둔 서버(`server.json`)가 살아 있으면 오류다(`TMUX_TMPDIR` 없이
  부른 경우, 지워진 소켓).
- **worktree 가 안 보이는 세션**은 작업의 자리(`…-t-<id>`)에서 열렸고 그 폴더가 사라졌을 때만 닫는다(복구로 되살아난 지운 작업).
  폴더가 있으면 저장소를 못 읽은 것이고, 자리가 아니면 사람의 세션이다. 읽지 못한 저장소가 있어도 멈춘다.
- **2 의 «Claude 없음» 은 다시 확인한다.** Claude 는 상태 파일을 제자리에 덮어써서 반쯤 쓰인 순간에는 읽히지 않는다. 세션이 있는데
  Claude 가 안 보이면 세 번까지 다시 읽는다. 세션이 있는데 pane 목록을 못 읽으면 «없음» 이 아니라 오류다.
- **3 은 `--untracked-files=normal` 을 명시하고, 7 은 `-c status.showUntrackedFiles=normal` 로 부른다.** 저장소 설정이 `no` 면
  `git status` 가 숨기고 **`git worktree remove` 도 추적 안 된 파일째 지웠다**(잼).
- **4 는 git 이 막지 않는다.** detached 에서 커밋한 worktree 를 지우니 그 커밋을 품은 ref 가 하나도 남지 않았다(잼).
- **무시된 파일은 함께 사라진다.** `.gitignore` 된 `.env` 만 있는 worktree 는 git 이 깨끗하다고 보고 지운다(잼). 막지 않고 적어 둔다.
- **5 는 네트워크 없이 센다**: `rev-list --count HEAD --not --remotes`. 원격이 없는 저장소에서는 새 worktree 도 전체 이력이
  세어지므로, 그때는 «다른 로컬 브랜치에 없는 커밋» 으로 센다. squash 머지 뒤 원격 브랜치가 지워지고 fetch `--prune` 했으면
  머지된 커밋도 «푸시 안 됨» 으로 남는다(잼). 그때는 `--force` 다. 브랜치는 남으므로 잃는 것은 없다.
- worktree 만 있으면 6 의 닫기를, 세션만 있으면 3~5·7 을 건너뛴다. 둘 다 없으면 1 이다.
- 하위 모듈이 있는 worktree 는 git 이 거절한다. 그대로 1 이고 세션은 이미 닫힌 뒤다(`세션 없음`).

## 종료 코드

| 코드 | 뜻 |
|---|---|
| 0 | 성공. start 가 «이미 있음» 이거나 이어 열었을 때도 0 이고, 그때 stdout 은 비어 있다 |
| 1 | 오류 — 잘못된 id·프롬프트, 저장소 없음, 같은 id 가 다른 저장소에 있음, 브랜치가 이미 있음, 없는 작업, git·tmux 실패, «제출됐는지 모름»(다시 보내지 말 것) |
| 3 | Claude 가 대화상자에서 사람을 기다린다 |
| 4 | start: 60초 안에 준비되지 않았다. 아무것도 보내지 않았고 세션은 남았다 |
| 5 | 하지 않았다, `--force` 로도 안 된다 — done: 작업 중·커밋 안 된 변경·떠 있는 커밋 / start: 입력창을 쓸 수 없었다 |
| 6 | start: 제출되지 않았고 되돌렸다. `mux agent prompt` 로 다시 보내도 된다 |
| 8 | done: 푸시 안 된 커밋 — `--force` 면 진행한다 |

2·7 은 agent API 의 read·wait 것이라 쓰지 않는다. 8 을 5 와 떼어 둔 것은 «`--force` 로 되는 것» 과 «안 되는 것» 을 스크립트가
갈라야 하기 때문이다(6 과 7 을 가른 것과 같은 이유).

| 오타 고치고 커밋 / push 까지 | 카드 2번 중 0번 | 재지 않음 | 재지 않음 |
| 새 기능 + 시험 + 문서 | 카드 2번 중 2번 | 카드 1번 중 0번 | 카드 1번 중 0번 |
| 운영 서버가 읽는 설정 변경 | 카드 1번 중 1번 | 카드 1번 중 0번 | 카드 1번 중 0번 |
| 요구 문서를 읽고 여러 단계 | 카드 2번 중 2번 | 카드 1번 중 0번 | 카드 1번 중 0번 |
| 요구가 모호함(«담당자가 정한다», 근거 없음) | 재지 않음 | 질문 2번 중 2번 | 질문 2번 중 2번 |

- 지금 문장: `이 작업은 사람이 이미 승인했다(collab-os 관문 카드 포함). 결정 카드는 내지 말고 끝까지 진행해.`
- 옛 문장: `… 카드를 내거나 확인을 묻지 말고 끝까지 진행해.` «확인을 묻지 말고» 는 요구가 모호할 때의 질문까지 막는 말이라 뺐다(사용자 결정).
  다만 잰 요구에서는 옛 문장으로도 물었다. 혼자 고르면 안 된다고 문서에 적힌 요구였고, 덜 뚜렷하게 모호한 것은 재지 않았다.

실제 작업 하나(`t-seedtest`, 파일 하나를 구체적으로 지시)는 멈추지 않았다. 표본은 작다.

- **멈춰도 `blocked` 가 아니다.** 카드를 글로 내고 턴을 끝내므로 상태는 `idle`, `mux agent wait` 는 0, `ls` 는 ✅ 다. `commits` 가 0 인
  것으로 알아보고 `mux agent read t-<id>` 로 카드를 읽는다. 대화상자가 아니라서 `mux agent prompt t-<id> "진행"` 으로 이어진다.
- **질문은 다르다.** 잰 네 번 모두 선택 대화상자로 물어 `blocked` 였고 `wait` 는 3 이다. 지나치지 않는다.
- **그대로 둔다(사용자 결정).** 관문이 옳게 멈춘 일도 있다(운영 설정). 끄거나 mux 가 문장을 붙이는 대신, 맡기는 쪽이 프롬프트에 승인을
  적는다. 문장은 위의 «지금 문장» 이고, 사람이 정말 승인한 일에만 적는다.
- 버린 것: `--approved` 로 mux 가 문장을 붙이기(700자에서 자리를 먹고 mux 가 남의 플러그인 문구를 알게 된다), `t-*` 에서 훅 끄기(멈추는
  게 맞던 일도 지나간다). 세션마다 설정을 주는 `--settings '{…}'` 는 명령줄에 남아 복구 때 인용이 풀린다.

## 백그라운드 에이전트를 띄운 워커

턴이 끝났어도 백그라운드 에이전트가 도는 동안 상태는 `busy` 이고(셸 명령을 돌리면 `shell`), 끝나면 `peer` 턴이 이어진 뒤 `idle` 이 된다
(2026-11-25 잰 것: 도구 없이 49초, `sleep 45` 각 한 번). 그래서 `wait` 와 `done` 은 그것을 기다린다. 다만 `mux agent read --after` 는
**프롬프트가 연 턴의 글**을 낸다 — 뒤의 `peer` 턴의 글이 아니라서 «기다리는 중» 같은 중간 글이 나올 수 있다.

- **표시**: `notifySessionLine` 의 이름 앞에 한 칸 ASCII 표시를 흐리게 둔다. 폭은 `fixed` 에 넣는다. 새 글리프를 쓰지 않는 것은
  ghostty 의 글꼴 대체 문제 때문이다. 판정은 이름만 보는 순수 함수 `TaskID(session)` 하나다. 묶기·정렬은 하지 않는다.
- **이벤트**: `MergeEvents` 가 보관본에서 되돌릴 때 `○ 종료`(상태 None)를 건너뛴다. 살아 있는 세션에 «종료» 는 늘 거짓이라 `t-*`
  만이 아니라 모든 세션에 적용한다. 보관본의 내용은 바꾸지 않는다.

## 사용자가 정한 것 (2026-11-25)

1. worktree 는 mux 가 만들고 저장소 옆에 둔다.
2. 씨앗 대화(`claude -p … /rename`, 모델 호출 없음)로 `claude --resume <id>` 모양을 만든다.
3. `done` 뒤 resurrect 저장을 한 번 부른다.
4. 이벤트 되돌리기에서 `○ 종료` 를 건너뛴다(모든 세션).
5. worktree 만 있고 프롬프트를 보낸 적이 없으면 이번에 보낸다.
6. `Claude 없음` 상태를 더한다. 이때 `start` 는 알리기만 한다.
7. e2e 여섯째 순서를 «커밋 → 8 → push → 성공» 으로 나눈다. 요청서 4절(푸시 안 된 커밋이면 멈춤)과 검증 6(커밋 후 done 성공)이
   서로 어긋났다.

## 알려진 한계

- **시작 커밋이 안 올라간 저장소**에서는 워커가 커밋하지 않았어도 `done` 이 8 이다. HEAD 에서 시작하므로 그 커밋도 «푸시 안 됨» 이다.
- **id 하나를 두 저장소에서 겹치지 않게 보는 범위**는 설정·`--repo`·지금 폴더·살아 있는 세션의 저장소다. 설정에 없는 저장소의 죽은
  작업은 보이지 않는다.
- **사용자가 만든 `t-…` 세션**도 패널에서 작업으로 표시되고 `ls` 에 `워크트리 없음` 으로 보인다. 판정은 이름뿐이다. `done` 은 닫지 않는다.
- **`git update-index --skip-worktree`·`--assume-unchanged`** 한 파일의 수정은 `git status` 와 `git worktree remove` 가 못 봐서 함께
  지워진다(잼). sparse-checkout 도 같은 표시를 써서 막으면 그 저장소의 `done` 이 늘 멈춘다. 막지 않는다.
- **확인과 닫기 사이의 짧은 틈**(닫기 바로 앞의 확인 뒤 수 ms)에 Claude 가 일을 시작하면 그 턴은 끊긴다.
- **`t-<id>` 가 서버의 마지막 세션이면** `done` 이 닫을 때 서버도 끝나 저장을 부르지 못한다. 다음에 서버가 뜨면 그 작업이 홈에서
  되살아날 수 있다(`워크트리 없음`). 평소에는 오래 가는 세션이 있어 생기지 않는다.
- **`start` 를 겹쳐 부르면** 뒤의 것은 기다리지 않고 1 로 끝난다(앞의 것이 60초까지 걸릴 수 있다).
- **Claude 를 올리면 다시 잴 것**: `-p --session-id … /rename` 이 모델을 부르지 않는가, 사람 턴 없는 대화가 `--resume` 되는가,
  `custom-title`·`origin.kind`·`entrypoint` 의 모양. 가짜 Claude 는 이것을 흉내만 낸다.

## 버린 것

- **`claude --worktree`** — 위.
- **제목을 `claude -n` 으로** — 복구 때 인용이 풀린다.
- **tmux.conf 의 `@resurrect-processes` 에 `"claude --session-id->claude --resume *"` 더하기** — 동작하겠지만 사용자의 설정을 고쳐야
  하고, 씨앗이 있으면 필요 없다. 재지 않았다.
- **post-restore 훅에서 mux 가 Claude 를 다시 띄우기** — 새 복구 로직이다.
- **`--continue`** — 폴더가 사라진 채 복구되면 홈 폴더의 무관한 대화를 잇는다. `--resume <id>` 는 엉뚱한 대화를 열지 않는다.
- **id 로 정하는 고정 UUID** — 같은 id 를 다시 쓰면 «already in use» 다.
